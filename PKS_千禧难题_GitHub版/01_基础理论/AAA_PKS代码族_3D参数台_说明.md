## 二、① 双波纹盘（本轮纠正的那一族）

### 2.1 旧版错在哪

旧版画的是 `z = A·sin(nθ)`：**沿圆周**起皱，像盘子边缘压出的花边。这是"周向驻波"，属于克拉德尼那一类。

### 2.2 原脚本实际做的

`22_双波纹盘最佳截面曲线.py` 根本不画参数曲线 `(x(t), y(t))`，而是把蛋的两个**分量拆开**，
各自以 `t` 为横轴当一条**截面曲线**（蓝 = `x_minus`，绿 = `y_add`），绕盘心转一圈 → 一张**双面**盘。

```
amp(t) = 1 / [ (1 + t/2π) · ln(n+1) ]

A(t) = amp(t) · a · [ 2·sin t / (b + √(b²−4k·cos t)) − t_min ]
B(t) = amp(t) · a · [ m·term₁ + term₂(t) + t_min ]

term₁ = −( √(1+k²) · ( −√(b²−4k) + √(b²+4k) ) ) / (2k)
term₂(t) = (1/(2√(1+k²))) · [ ((k²−1)/k)·b + ((k²+1)/k)·√(b²−4k cos t) ]
           − [ b(k²−1) + √(b²−4k)·(1+k²) ] / (2k√(1+k²))

a = 2π ，m = 2/3 ，k = 2/3 ，b = 5/3
t_min = 2π/(n+1) ，t ∈ [t_min, 2π + 2nπ]
```

- **波纹沿半径方向**，一圈圈往外走；**振幅往外衰减**（`amp ∝ 1/t` 的平移变体 × `1/ln(n+1)` 归一化）。
- `n` 越大：纹越密、盘越薄。实测最大厚径比（k=2/3, b=5/3）：

| n | 1 | 2 | 3 | 5 | 8 | 12 |
|---|---|---|---|---|---|---|
| 最大厚径比 | **2.207** | 0.581 | 0.258 | **0.0925** | 0.0369 | 0.0172 |

`n=1` 时厚度**比半径还大**，已经不像"盘"而是个纺锤——这不是画错，是 `ln(n+1)=ln2=0.693` 的归一化给得太松。
- 蓝面全部落在 `z<0`、绿面全部落在 `z>0`，两面**不相交** —— 所以能围成一个合法的闭合截面。

### 2.3 27 号：衰减内化

不再外乘 `amp`，改成让蛋自己的参数随时间演化：

```
k(t) = 1/T = 1/2π
b(t) = 2t/(T√t) = 2√t / T
```

**坑**：`b² − 4k = 4t/T² − 4/T`，**当 `t < T = 2π` 时为负**。原脚本直接 `np.sqrt()`，会得到 `NaN`。
本页照实处理：从 `t = 2π` 起画，内圈留空，读数里报"无效采样点"。

另外 27 号的截面厚度剖面比 22 号**更不均**（同一组 n=5，厚度在 0.7 与 11.7 之间来回跳），
因为它 `b(t)` 在变、`term₂` 也跟着变。**这不是画错，是这条式子的真实行为。**

### 2.4 30 号：四方案对比

把 4 组（`amp1`/`amp2` × 旋转 90°/180°）平移到 `z = 0/−12/−24/−36` 做对照。
**旋转 90° 只是把同一条截面在平面内转个方向**，不改变形状；所以它不是新方程，是同一族的排版对比。
本页没有复刻这个排版（一个视口里放四个盘反而看不清），只复刻了方程本身。

## 三、② 蛋螺旋（Die Ei-Kurve · √n 缩放）

```
k = F_{n+1}/F_{n+2} ， b = F_{n+3}/F_{n+2}     ← 随 n 收敛到 1/φ = 0.618 与 φ = 1.618
r(φ) = amp · [ z₀ − √( z₀² − 4·cosφ·sinα / √(sin²φ + cos²φ·cos²α) ) ] / (2·cosφ·sinα)
x = r·sinφ ， y = r·cosφ ， tanα = k ， z₀ = b ， amp = √n
叠层：z_n = (n−1)·Δz ，第 n 层转 θ_n = (n−1)/(N−1) · 2520°
```

- **一个反直觉点**：`n` 增大时形状几乎不变，只是**整体按 √n 放大**——因为 `(k,b)` 已经收敛到黄金值。
  所以 72 层叠起来不是"越来越像蛋"，而是"同样形状越来越大 + 一直在转"。
- `φ = π/2, 3π/2` 处 `cosφ = 0`，分母为零。原脚本用 `valid_mask` 跳过，本页也跳过 → 每条曲线**两个小缺口**，不是画错。
- 原脚本出的是 2D 叠图 GIF；本页把每层抬一个 `z`，另加一条红色**脊线**（每层蛋尖连起来）——
  **脊线是我加的**，原脚本没有，只为让"螺旋"显形。
- 默认 `总旋转 540°`（41°/层）便于看清嵌套；原脚本是 **2520°**（194°/层，相邻两层几乎翻转重叠），可自行拖回去。

## 四、③ 螺旋锥管（指数螺旋 + 管波动纹）

```
螺旋线：R(t) = R_top·e^{b·t} ， b = ln(R_bot/R_top) ， R_top = R_bot/2 − tan(α)·h
        θ(t) = 2π·turns·t ， z(t) = h·(e^{bt} − 1)/(e^b − 1)
扭转：  ψ(t) = twist·2π·turns·t                    （linear）
        ψ(t) = twist·2π·turns·(2^{3t}−1)/(2³−1)     （exponential，原脚本默认）
断面：  r_s(t) = amp·(1 − taper·t)                   （原脚本 a[] = linspace(1, 1/3) → taper = 2/3）
波纹：  相位 = Bands·(φ^{p·t} − 1)/(φ^p − 1) ，锯齿 = 2 − (相位 mod 1) ∈ (1,2]
        断面半径 × [1 + cAmp·(锯齿 − 1.5)]
```

- **波纹不等间距**是关键：相位是 `φ` 的幂的积分，所以**下疏上密**。
  原脚本 `_precompute_exp_wave` 里那段 `minimize` 就是在反解 `k`，让总带数正好落在 **47 带**。
  本页把"总带数"做成滑条（等价、可数），省掉优化这一步。
- **降级说明（重要）**：原脚本从 `start/end 舒伯格蛋咬一口曲线.dxf` 读两个断面，沿 `t` 做**首尾渐变**，
  再乘 `a[i]`；本页断面是**圆 + 波纹**，没有做断面渐变。要精确复原得读 DXF。
- 参考值：`R_bot=108, h=144, α=13.28° → R_top=20.0, b=0.993`（与脚本 `__main__` 一致）。

### 4-1 圆周阵列（通用机制，六族全支持）

```
applyArray(obj, P, fam):
  n = clamp(round(P.reps), 1, 12)
  对 k = 0 … n−1：
    c = obj.clone(true)                      # 深拷贝：材质/几何各自独立
    c.rotation[ fam.zAxis ] = k · 360°/n     # 绕【该族的对称轴】
    tintCopy(c, k, n)                        # 副本色相平移 ±0.08，肉眼可区分
  wrap.userData.reps = n
```

| 族 | 对称轴（`zAxis`） | 说明 |
|---|---|---|
| ① 双波纹盘 | `y`（竖直） | 盘面法线 |
| ② 蛋螺旋 | `z`（平面法线） | 叠层面法线 |
| ③ 螺旋锥管 | `y`（竖直） | 锥轴 |
| ④ 蛋形均轮 | `z`（平面法线） | 轮面法线 |
| ⑤ 钟形水轮 | `y`（竖直） | 水轮轴 |
| ⑥ 双曲锥 | `y`（竖直） | 锥轴 |

**三个容易踩的坑（都已踩过并修掉）：**

1. **变换 ≠ 数据**。`Object3D.rotation` 是变换矩阵，顶点数据本身不旋转。
   验证 n 重对称必须比较**施加旋转后的世界坐标**，不能直接比 `geometry.attributes.position`。
2. **副本必须各自 `material.clone()`**。直接共享材质 ⇒ 改一份颜色，全部跟着变（串色）。
3. **坐标系辨析**：族③ 的中心线返回 `[x, y(竖直), z]`，即 three.js 里 **y 才是竖直方向**；
   `fam.zAxis:'y'` 表示绕**竖直轴**转（题目口语称"绕 z 轴"）。
   反算时旋转只作用于 x/z 分量、y 不变：`bx = x·cosφ + z·sinφ`，`bz = −x·sinφ + z·cosφ`。

### 4-2 族③：管子为什么看着"被封住了"（真 bug · 根因修复）

**现象**：管入口和出口都是封闭的。
**初判**：以为是不透明 `DoubleSide` 材质的视觉封闭。
**真根因**：**Frenet 标架在曲线两端退化**。

Frenet 标架用中心差分 `d₁` 与二阶差分 `d₂` 构造：

- `t = 0` 时 `c₂ = C(max(0, t−hh)) = C(0) = c₀` ⇒ `d₂ = d₁` ⇒ 两者平行
- `t = 1` 时 `c₁ = C(min(1, t+hh)) = C(1) = c₀` ⇒ `d₂ = −d₁` ⇒ 两者平行

⇒ `cross3(T, N) = 0` ⇒ 副法向 `B` 退化成 `[0,0,0]` ⇒
**管口断面被压扁成一条线**，视觉上正是"两端被封住"。

> 实测证据：真机探针打印原始采样点，`s240` 的 `B` 向量 = `[0,0,0]`。
> 这是几何 bug，不是材质问题。

**修复**：改用**旋转最小化标架（RMF · 双反射法）** `rmfFrames(C, NT, ta, tb)`。
RMF 全程保证 T/N/B 正交且非退化，两端不塌。附带好处：

> RMF **不含曲线自身的挠率** ⇒ 红线缠绕角 **严格等于**显式 twist 角。
> 修复前实测 −988.8°（错），修复后精确 −1080°（3.00 圈），与读数逐档吻合。

配套的视觉改造：

| 改造 | 做法 | 为什么 |
|---|---|---|
| 管体 | `MeshPhongMaterial({side:DoubleSide, transparent:true, opacity:0.80, depthWrite:false})` | 只画侧壁、两端不封盖，能看进管内 |
| 入口/出口亮圈 | `TubeGeometry`（**不是 `THREE.Line`**） | WebGL 不支持 `linewidth>1`，用 Line 只有 1 px，看不见断口 |
| 断口盘 | `RingGeometry` + opacity 0.16 | 出口管径只有入口 1/3，只有环的话只是个小点 |
| 红色扭转母线 | `TubeGeometry`（半径 `max(0.25, tr·0.075)`） | 同上，Line 看不见 |
| 族⑤ 叶片 | 标架也改 RMF | 叶片断面原来也会被压扁 |

### 4-3 几何反算：两个方向相反的按钮（族③ 专用）

**需求原文**：「增加两种按钮，根据已知圆周阵列个数比如 4 个，锥顶和锥底直径等现有参数，
自动算出在曲面不重叠的情况的管径最大允许的参数。另一种，反过来，
保证现场生成的螺旋管曲面不相交的情况，固定螺旋管出&入口管径，锥顶和锥底直径等现有参数，
自动算出圆周阵列最大个数。」

#### 判据（保守充分条件）

把每份管看成沿中心线扫掠的**圆截面管**。局部管半径

```
r_s(t) = tr · k(t) ，   k(t) = (1 − taper·t) · wave(t)     （无量纲）
```

对任意两份（份 0 的 `t₁` 点 vs 第 `g` 份的 `t₂` 点），只要中心线距离 `d` 满足

```
d(t₁,t₂)  >  tr · ( k(t₁) + k(t₂) )
```

则两个管**一定不相交**（把每份管包含在沿中心线的球带里，球带不重叠 ⇒ 管不重叠）。

⇒ **tr 上限 = min over 所有点对 d / (k₁+k₂)**

因为 `tr` 在判据里**只线性出现**，所以上限可以**一次遍历直接出解，不需要二分**（实测 n=12 时约 1 ms）。

两类约束都要查：

| 类别 | 含义 | 采样方式 |
|---|---|---|
| (A) 邻份 | 份 0 与第 `g` 份，`g = 1…n−1`，绕对称轴转 `dφ = 2πg/n` | 全点对（`O(MT²)`） |
| (B) 圈间 | **同一份内部**相隔 `m` 圈，`m = 1…floor(turns)` | `t₂ = t₁ + m/turns`（真正角对齐的一圈），±半圈窗口内取真实最近点 |

> **(B) 类的坑**：不能用 turn-index 过滤。`t=0.499` 与 `t=0.501` 是**同一条曲线的相邻点**，
> 不是不同圈。真正的一圈对齐是 `t₂ = t₁ + m/turns`。

#### 实现要点

| 要点 | 做法 |
|---|---|
| 公式与渲染同源 | 抽出 `f3Geo(P)` 几何核心（`C(t)` / `wave(t)` / `rs(t)`），渲染与反算共用 ⇒ 不会出现"算出来的与画出来的不符" |
| 全页统一采样 | `F3_MT = 160`，读数、按钮、缓存**必须一致**。曾因读数用 140、按钮用 160，导致"按钮刚应用完读数却说不安全" |
| 缓存 | `lim(n)` 只依赖几何参数（与 `tr` 无关）⇒ 拖管半径滑条时缓存命中，读数刷新瞬时 |
| 反解 n | `lim(n)` 单调不增 ⇒ 二分查找，最多 4 次求值 |
| 刻度吸附 | 滑条 `min=1, step=0.1`；应用值先**向下取整**到 0.1（宁可保守），再吸附刻度 ⇒ "滑条显示值 == 模型实际值" |
| 旧结果失效 | 手动改 `tr`/`reps` 后清空上次的反算结果，避免误导 |

     `slack = 到邻管中心线的最近距离 − 邻管该处局部半径`
     ⇒ `slack > 0` 表示管壁全部在邻管之外（不穿插）；`slack < 0` 表示确实穿插

### 4-4 依赖路径加固：three.js 不再"挑服务根"（2026-10-27 增补）

**原来的隐患**：页面写死 `<script src="../_vendor/three.min.js">`。
只要静态服务的根不是仓库根（例如图省事把 `01_基础理论/` 当根），
`../_vendor/` 就跑到服务根之外 ⇒ 404 ⇒ `THREE` 未定义 ⇒ 主脚本 `initGL` 抛
`ReferenceError` ⇒ **参数面板照常显示、3D 区域一片空白**，不开控制台看不出原因。

**两层修法**：

| 层 | 做法 | 效果 |
|---|---|---|
| ① 文件层（主路） | `01_基础理论/_vendor/three.min.js` 与仓库根 `_vendor/three.min.js` 建为**同一 inode 的硬链接**（`nlink=4`，**零额外磁盘**） | 两种服务根下 `../_vendor/` 与 `./_vendor/` 都能命中，纯离线可用 |
| ② 代码层（兜底） | 主脚本**之前**插入同步加载器：`./_vendor/` → `./_vendor/three.min.js` → jsDelivr CDN（r128 同版），全落空则页面顶部挂**红色横幅**写明修法 | 不再出现"沉默留白"；最坏情况也会明确报因 |

用同步 `XMLHttpRequest`（`open(..., false)`）是**故意**的：若改成异步，主脚本会抢在前头执行、照样抛错。
实测本机 **CDN 不可达**（jsDelivr 返回 000），所以 ① 才是真正起作用的那条。

**实测证据**（临时以 `01_基础理论/` 为根起 8844 服务）：

```
17:55:47  GET /_vendor/three.min.js → 404   （建硬链接前：THREE 未定义，仅红色横幅）
17:56:14  GET /_vendor/three.min.js → 200   （建硬链接后：THREE r128，canvas 1130×518）
```

修复后错误根下截图确认：螺旋锥管 + 红色扭转母线正常渲染，无横幅。

> **注意**：`_vendor/three.min.js` 的 4 个路径（仓库根 / `01_基础理论/` × 主目录 / 镜像目录）
> 现为**同一 inode**。以后要换 three.js 版本，**必须四个路径一起换**（或直接删除三个硬链接后重建），
> 否则会出现"某个根下还是旧版"的诡异现象。

## 六、⑤ 钟形水轮

```
母线半径：r(t) = √[ 1/(b − t·sinα)² − (t·cosα)² ]
中心线：  x = r·sin(3ft) ， y = r·cos(3ft) ， z = −t·z_v ， t ∈ [0, 2π/3]
```

- 三个**容易看漏**的细节，本页都按原脚本实现：

### 6-1 叶片横断面相位角（2026-10-27 新增，可调）

**需求**：叶片的那条 2D 横断面曲线要能整体绕原点旋转，且约定「x 正半轴 = 曲线起点」。

**几何事实**：断面 `x_s(θ)=−aπ sinθ/θ, y_s(θ)=aπ cosθ/θ`（θ∈[π, 2.5π]）
等价于**极坐标**写法 —— 半径 `r = aπ/θ`、方位角 `φ = θ + 90°`，逆时针展开 270°。
所以原始图的**起点**（θ=π）落在方位角 **−90°**（−y 方向），并不在 x 正半轴上。

**本页的处理**（两件事合成一个旋转）：

| 步骤 | 内容 |
|---|---|
| ① 锚定 | 把起点从 −90° 转到 **0°**（x 正半轴）⇒ 需要 +90° |
| ② 相位 | 再按滑条 `横断面相位角 φ₀`（0–360°，整度，**逆时针为正**）继续旋转 |

⇒ **施加在原始图上的总旋转 = φ₀ + 90°**。

| φ₀ | 起点落点 | 相当于原始图旋转 | 备注 |
|---|---|---|---|
| **0°（默认）** | x 正半轴 | +90° | 符合「x 正半轴为曲线起点」的约定 |
| 90° | +y | +180° | |
| 180° | −x | +270° | |
| **270°** | −y | +360° ≡ 不旋转 | **与原脚本朝向完全一致**（回归值） |

**实现要点**：

- 断面公式抽成单一函数 `f5SecPoint(P, s, τ)`，**3D 渲染与 2D 预览共用** ⇒ 预览画的就是模型上的那条曲线，不会"预览一套、模型另一套"。
- 读数区新增两行：`横断面起点方位`（= φ₀）、`对原始 2D 图的旋转`（= (φ₀+90) mod 360）。
- 参数台下方新增 **2D 预览画布**：同心圆（模型单位）+ x/y 轴 + 外缘/内缘两条断面曲线 + 红点（起点）+ 橙色射线（起点方位）。
  视野按**模型单位自适应**：`Rv = max(0.25, 1.15·0.30·bl)`，所以「叶片尺度」无论调到多大，曲线都占满画面。
- 顺带把 `f5Build` 的标架说明从「Frenet」改成 **RMF 旋转最小化标架**（本页上一轮已改，note 里此前还写着 Frenet，属笔误，此处一并更正）。

**验证**（新增 13 项 DOM 桩断言 + 26 项真机 CDP 断言）：

- 几何：φ₀ = 0/90/180/270 ⇒ 起点分别落在 +x/+y/−x/−y；只旋转不平移（起点到原点距离不变）；
  总旋转 = φ₀+90°（中点 θ=2π 由 +y 转到 −x）；φ₀=270° 时断面与原始 2D 方程**逐点一致**（最大偏差 < 1e-12）。
- **像素级真机验证**：直接读 2D 预览画布的 `getImageData`，反解红色起点点的方位角，
  实测 **0.55° / 90.54° / 179.46° / 269.45°**，与滑条值逐档吻合（±1.5° 内；0.5° 偏差来自红点白圈的像素质心）。
  这一条比"参数变了"强得多 —— 它证明预览画出来的**位置**真的对。
- 3D：0° 与 180° 的叶片顶点确实不同（顶点数不变、位置改变）。

### 6-2 2D 预览面板的镜像按钮（2026-10-27 新增）

**需求原文**：「这个红圈位置增加一个镜像按钮，它会让此 2D 曲线图以 y 轴为镜子翻转，
同理 螺旋锥管的 管横截面·2D 预览（局部 xy 平面）的右边也要加」。

**落点**：2D 预览浮窗 `#secfp`（左下角可拖动 / 可收起）的**标题行右侧**，
族③ 螺旋锥管与族⑤ 钟形水轮**共用同一个按钮**（`#secMir`，文案 `⇋ 镜像 y`）。

#### 关键设计决策：镜像的是几何，不是像素

这是这一节唯一值得记住的事。按钮**没有**去翻画布的 `ctx`（没有 `ctx.scale(-1,1)`），
而是在**几何函数内部**改符号：

```
反射： (x, y) → (−x, y)        # 以 y 轴为镜
参数： mirX = 1（原样，默认） / −1（镜像）
```

| 位置 | 改法 | 为什么这样做 |
|---|---|---|
| 族⑤ `f5SecPoint(P,s,τ)` | 算完 `(px,py)` 后 `if(P.mirX<0) px = −px` | 3D 叶片扫掠与 2D 预览**共用这一个函数** |
| 族③ `f3SecLocal(P)` | `secCurve(secType)` → 按 `secAz` 旋转 → `if(mir) px = −px` | 同上，3D 管断面与 2D 预览共用 |

⇒ 一按按钮，**预览与模型同时翻**，面板"两者共用同一条曲线"的承诺不被破坏。
若只翻画布，预览会与模型不符 —— 那是最容易犯又最难发现的错。

#### 镜像带来的两个连锁事实

1. **起点方位角变了**：`方位' = 180° − 方位`。
   所以两条预览函数的橙色射线不再直接用 `secAz` / `secPhi` 画，
   而是**由实际起点反算** `atan2(q0.y, q0.x)`，保证射线始终穿过红点：
   ```js
   /* 族⑤ */
   var q0 = f5SecPoint(P, 0, Math.PI);
   var phi = Math.atan2(q0[1], q0[0]);  if(phi<0) phi += TAU;
   /* 族③ */
   var st = cur[0];
   var phi = Math.atan2(st[1], st[0]);  if(phi<0) phi += TAU;
   ```
   > 这条反算顺带修掉了原来的一个隐性不一致：以前射线用的是滑条值，
   > 一旦断面曲线被归一化平移过，射线与红点就可能差几度。

2. **反射是等距变换** ⇒ **面积不变、外接半径不变**。
   这两条被写成断言，正是用来证伪"这不是真反射"（比如误写成缩放或剪切）。

| 族 | 新增读数行 | 镜像时显示 |

#### 验证（27 项全绿 · `_verify_mirror.js`）

| C14 | 漏斗·平方 `t²` | `r=1/t_shape²`，`z=−2ln(t_shape)/lnφ` | 是（**上升**，符号相反） | 1 |

`φ = (√5−1)/2 = 0.618…`，`ln φ = −0.48121`。漏斗面方程 `z = ln(1/r)/lnφ`
—— 因为 `lnφ < 0`，所以「r 越小 z 越大」⇒ **漏斗开口朝上、底部收窄**。

**C10 不是真对数螺线**（这条容易误标）：`r=r₀/t_s` 是**双曲**关系，
`d(ln r)/dT` 并非常数；只有 **C12** 是 `d ln r/dT` 恒定的真对数螺线。
C13 也是真对数螺线（因为 `2^{−t/2π}` 就是 `e^{−t·ln2/2π}`），且**末端曲率上限最低 ⇒ 工程上最友好**。

**C14 的符号要照抄并标注**：它对 `z` 的符号与其它四个漏斗脚本**相反**、且多一个 2 倍因子。
本页不"顺手统一"，而是照抄并在 note 里写明。

## 八、本页十一格共同的边界

1. **只复刻方程，不复刻文件 I/O**：DXF 读入（③⑤）、`trimesh` 导出 OBJ（⑤）、Rhino 的 `AddInterpCurve` 插值（①②），都没有搬。
   （⑦⑧⑨ 的断面是**离线抽好**的 120 点折线，存成字符串常量，所以不需要读 DXF 也能跑。）
2. **网格是三角面**，分辨率取到能看清纹路为止，**不是加工级精度**。
3. **各族独立**，不强行塞进同一条公式。仓库里它们确实同根（都从蛋 / 双曲线来），但"同根"是叙述，不是可互推的等式。
4. 画面里的 `z 向夸大` 一律**明确标注**（双波纹盘真实厚径比 1:10.8，默认夸大到 8 倍才看得清纹路）。
5. **中心线库是"分类维度"不是"统一公式"**：C1–C14 之间只有族内（C1/C2/C3 指数族、C10–C14 漏斗族）有明确互推关系，
   跨族并列是为了**选型**（同参数下哪条更平缓、曲率上限更低），不是为了证明等价。
