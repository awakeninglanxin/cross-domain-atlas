## 零、这个演示在做什么

原版只有两条 `Input`，全部内容就是**两个递归定义**：

> 把 **p** 个圆环摆成一圈；再在**每个环的主圆上**摆 p 个更小的环；如此递归 **g** 层。

`generate` 只有 6 行，但环数按 `1 + p + p² + … + p^g` 爆炸：

| p | g=1 | g=2 | g=3 | g=4 |
| --- | --- | --- | --- | --- |
| 2 | 3 | 7 | 15 | **31** |
| 3 | **4** | **13** | **40** | **121** |
| 4 | 5 | 21 | 85 | **341** |

nb 的默认是 `a=5, p=3, g=1` ⇒ **4 只环**：一只横躺的大环 + 3 只挂在它主圆上的竖环。

三条容易看漏的几何要点：

1. **子环的中心恰好落在父环的主圆上**（不是「附近」，是真距离 = 0）。
2. **主半径逐层严格减半**：`sU(L) = a / 2^L`。
3. **管半径恒为 0.5**（`generate` 的基例里写死 `{{u, v, t, 0.5}}`）—— 所以层数一深，环就「胖」到管子比主圆还粗。

## 一、nb 的定义（逐字复刻，未作任何改动）

```mathematica
torus[u_, v_, t_, r_] := Module[{sU, sV, sW, w = u×v},
  {sU, sV, sW} = 1. Sqrt[{u.u, v.v, w.w}];
  t + {Cos[φ](sU + r Cos[θ]), r Sin[θ], Sin[φ](sU + r Cos[θ])} . {u/sU, v/sV, w/sW}]

generate[{u_, v_, t_, _}, 0] := {{u, v, t, 0.5}}

generate[{u_, v_, t_, n_}, depth_] := Module[{sU, sV, sW, w = u×v, α = 2.π/n, i, t1, u1, v1, p},
  {sU, sV, sW} = 1. Sqrt[{u.u, v.v, w.w}];
  p = Table[t1 = t + sU {Cos[α i], 0, Sin[α i]} . {u/sU, v/sV, w/sW};
            u1 = (sU/(2 sV)) v;
            v1 = (t1 - t)×v;
            generate[{u1, v1, t1, n}, depth - 1], {i, n}];
  Flatten[Append[p, generate[{u, v, t, n}, 0]], 1]]
```

```mathematica
Manipulate[
  h = generate[1.{{a,0,0},{0,a,0},{0,0,0}, p}, g];
  hlist = Apply[torus, h, 1];
  Show[ParametricPlot3D[hlist, {φ,0,2π}, {θ,0,2π},
        Boxed->False, Axes->False, PlotPoints->20, Mesh->None,
        PerformanceGoal->"Speed"],
       PlotRange->All, ImageSize->{500,350}],
  {{a,5,"thickness"},10,1,-1},
  {{p,3,"number of tori"},Range[2,4]},
  {{g,1,"level"},Range[4]},
  SaveDefinitions->True, TrackedSymbols->True]
```

### 1.1 逐句对应

| nb 片段 | 含义 | 页面里的位置 |
| --- | --- | --- |
| `torus[u_,v_,t_,r_]` | 一只环的参数曲面，`φ` 绕主圆、`θ` 绕管 | `torusPt(tor, phi, th)` |
| `{sU,sV,sW}=1.Sqrt[{u.u,v.v,w.w}]` | 三条基向量的模长 | `makeTor` 里 `M3.len` |
| `. {u/sU, v/sV, w/sW}` | 用**单位化**基向量装配 | `tor.uh / tor.vh / tor.wh` |
| `generate[{u_,v_,t_,_},0] := {{u,v,t,0.5}}` | 基例，**管半径写死 0.5** | `rec(..., depth, 0)` 分支 |
| `α = 2.π/n`；`i = 1..n` | p 个子环均分 360° | `rec` 的 `for (i = 0; i < p; i++)`，角度用 `2π i / p`（见 §1.2） |
| `u1 = (sU/(2 sV)) v` | 子环的 u 基 | `M3.mul(v, sU / (2 * sV))` |
| `v1 = (t1 − t)×v` | 子环的 v 基（**叉积**，保证 ⟂ u1） | `M3.cross(M3.sub(t1, t), v)` |
| `Flatten[Append[p, generate[{u,v,t,n},0]], 1]` | **子环在前、自身在后** | `rec` 末尾 `return kids.concat([self])` |
| `1.{{a,0,0},{0,a,0},{0,0,0},p}` | 初值：u=(a,0,0)、v=(0,a,0)、t=原点 | `rec([a,0,0],[0,a,0],[0,0,0], g, 0)` |
| `Boxed->False, Axes->False` | 无盒无轴 | 画布只画曲面 |
| `PlotPoints->20` | 每方向 20 点 | 改成**自适应**（见 §2.4） |
| `ImageSize->{500,350}` | 画布 500:350 | `canvas.cnb{aspect-ratio:500/350}` |
| `ViewPoint->{0,0,100}` + `ViewAngle->0.01` | 沿 −z 的**正交**投影 | 「nb 原版」视角按钮 |
| `{{a,5,"thickness"},10,1,-1}` | a 滑块，范围 10→1，**步长 −1** | 滑块 1..10（步长取正，方向无实质差别） |
| `{{p,3,...},Range[2,4]}` | p ∈ {2,3,4} | ② 整数框 |
| `{{g,1,...},Range[4]}` | g ∈ {1,2,3,4} | ③ 整数框 |

### 1.2 `i = 1..n` vs 页面里的 `i = 0..n−1`

Mathematica 的 `Table[..., {i, n}]` 取 `i = 1, 2, …, n`，角度是 `α·i = 2π i/n`。
页面里写 `2π i / p`、`i = 0..p−1`，角度集合是 `{0, 2π/p, …, 2π(p−1)/p}`。
两者是**同一个集合**（差一个 `2π` 的整体旋转，且都是绕主环轴均匀 p 等分），
子环到主环圆心的距离、相邻子环的夹角、递归结构全部一致。这只是参数起点的选择，不改几何。

## 二、几个必须先讲清的技术点

### 2.1 拼接顺序 = **子环在前、自身在后** ⇒ 数组末位是主环（L0）

`Flatten[Append[p, generate[…, 0]], 1]` 把子环列表 `p` 放前面、把自己（基例）**追加到末尾**。

所以 `hlist` 的**最后一只**是主环，**前 p 只**是第 1 层子环。
页面的 `sceneOf` 忠实保留这个顺序（`return kids.concat([self])`），`levelCount` / 层级账本都按此对齐。

### 2.2 主半径逐层减半，管半径不变

`u1 = (sU / (2 sV)) · v` 而 `sV = |v|`，故 `|u1| = sU/2`。于是

```
sU(L) = a / 2^L          （L 为「距根层数」，L0 是主环）
|v1|  = sU · |v|          （且 u1 ⟂ v1，因为 v1 = (t1−t)×v 必垂直于 v）
```

管半径 `r ≡ 0.5` 一路不变。所以当 `a/2^L < 0.5`（即 `L > log₂ a`）时，最深那层就是「胖珠」而不像环。
页面「层级账本」把 `sU(L)` 与 `r` 并排列出来，一眼能看到这件事。

### 2.3 nb 默认视角是**退化的**（这条很关键）

`ViewPoint->{0,0,100}` 沿 −z、`ViewAngle->0.01` 正交。此时：

- 主环躺在 **xz 平面**，从 −z 看过去，**主环中脊被压成一条水平直线**（屏幕 y 恒为 0，x 跨度恰为 `2·sU`）。
- p=3 的三个子环中心都落在 xz 平面的主圆上，**投影两两重合，只给出 2 个位置**（屏幕 x = −2.5, −2.5, +5.0）。

也就是说 —— **nb 默认那一帧其实看不清结构**。这不是页面的近似，是原版 `ViewPoint` 就如此。
页面把这条写进了断言（参考测试 F 区 4 项、「nb 原版」视角按钮旁边的坐标读数），
并额外提供 3/4 视角、另一侧 3/4、正视、俯视 —— **默认就用 3/4 视角**，因为那才看得出「环套环」。

### 2.4 曲面细分数：从固定 20 点改成自适应

原版 `PlotPoints->20` 是**固定**的。本页按屏幕上的实际周长给段数：

```
φ 段数 M = clamp(偶数化( 2π·sU·scale·q / 9 ), 6, 128)     ← 主圆在屏幕上的周长
θ 段数 K = clamp(偶数化( 2π·r ·scale·q / 9 ), 4, 28)      ← 管截面在屏幕上的周长
```

`q` 是「精细度倍率」（滑块 0.6..1.6），播放旋转时会再乘 0.62 降档保帧率。
效果：小环自动用少段数（不浪费面片），大环自动用多段数（不出现多边形棱角）。

⚠ **`S.qual` 是「越大越细」，所以是乘不是除。** 一开始写成了 `circ / (9*q)`，方向反了，被桩测抓出来。

### 2.5 相机是**绕 z 轴**公转的 —— 以及由此引出的「半圈对称」

```
eye = c + [cos(pit)·cos(yaw), cos(pit)·sin(yaw), sin(pit)] · 1e4      （c = 包围球中心）
up  = [0, 0, 1]                                                       （|sin pit| < 0.999 时）
```

即方位角 `yaw` 在 **xy 平面**里转，`pit` 是相对 xy 平面的仰角。正交投影的屏幕坐标只取决于
`(right, up, target, scale)`，沿视线方向的位置无关 —— 于是

```
yaw → yaw + 180°    ⟺    screen₂(p) = screen₁( R(p − c) + c )，   R = 绕 z 轴转 180°
```

也就是「**把整个场景绕过包围盒中心的 z 轴转 180°**」，而不是绕原点。

**这条直接决定了 GIF 该扫多少度。** 场景本身在某些 p 下就有这个对称性：

| p | 子环方位角集合 | 在 `α ↦ 180° − α` 下 | 绕 z 转 180° 自重合？ |
| --- | --- | --- | --- |
| 2 | {0°, 180°} | {180°, 0°} —— 封闭 | **是** |
| 3 | {0°, 120°, 240°} | {180°, 60°, 300°} —— 不封闭 | 否 |
| 4 | {0°, 90°, 180°, 270°} | {180°, 90°, 0°, 270°} —— 封闭 | **是** |

所以 **p 为偶数时，360° 扫描的后半圈与前半圈逐像素相同**（实测帧 0 与帧 15：平均灰度差 0.013/255，99.73% 像素完全相同）。
页面的 `hasHalfTurnZ(sc)` 判定这件事（逐只环比 `(t, sU, r, 轴向±)` —— 因为 `u`、`v` 各自变号对应同一张面），
`gifSpan(sc)` 据此把扫描范围定成 **180°（p 偶）或 360°（p 奇）**。
帧数不变，但每帧都是新画面，角分辨率反而翻倍。

⚠ 判定要做对需要两个细节，我第一版两个都错了：
1. **旋转轴要过包围盒中心 `c`**（正交相机的 target 是 c），不是过原点；
2. **一只环的面只由 `(中心 t, 主半径 sU, 管半径 r, 轴向 ŵ 可取±)` 决定** ——
   `u→−u` 且/或 `v→−v` 时代入 `φ→π−φ` / `θ→−θ` 得到同一张面，所以不能直接比 `u`、`v`。

## 三、自写的 3D 内核 `_shared/mini3d.js`

三页共用（ChartForATorus / DiagonalsOfPolyhedra / RecursiveExercisesVITori），纯 Canvas2D、零依赖。

```
世界坐标 → lookAt 正交基 → 正交投影 → 深度排序(painter) → 绘制
光照：法向转到相机空间（光固定随相机），环境光 + 双方向光 Lambert
图元：四边形 / 线段 / 折线 / 球 / 文字，统一进一个列表按深度排序
```

关键接口：`cam` `camOrtho` `view` `proj` `pxRadius` `shade` `List(quad/line/polyline/sphere/text/flush)` `bboxOf` `sphereOf` `orbit`。

**本页没有改动这个内核**（只在多面体页改过 `drawQuad` 的 n 边形质心与 `seal` 开关），
内核自测 37 项本页完成后重跑仍全绿。

### 11.2 「多级」= g：从 1–4 扩到 1–7

nb 的 `{{g,1,"level"},Range[4]}` 只到 4 级。本页把滑块放到 **1–7，默认 7**（`1+2+…+2⁷ = 255` 只环）。

### 11.3 自相似改造：把两个常量变成旋钮

nb 原文有两处写死的常量，本页只把常量换成参数、**两条定义一个字没动**：

| nb 原文 | 本页 | 含义 |
| --- | --- | --- |
| `u1 = (sU/(2 sV)) v` 的 `1/2` | `q`（0.30–0.75） | 每级主半径比：`sU(L) = a·q^L` |
| 基例 `{{u,v,t,0.5}}` 的 `0.5` | `ρ·sU` | 管半径按级等比：`r(L) = ρ·sU(L)` |

两者一上就是「**比例匀称、梯度一致**」——`q` 和 `ρ` 全级恒定，没有哪一级特殊。
`q=0.5, ρ=0.5/sU` 时严格退化为 nb 原版（面板②的下拉框可秒切）。

### 11.4 关键结论：不重叠的**充要条件**是 ρ ≤ R\*，而 R\* 只有一个数

原来只写了父子与兄弟两条：

```
① 父子：sU(L+1) ≥ r(L)+r(L+1)  ⇒  ρ ≤ q/(1+q)
② 同层兄弟：sin(π/p) ≥ q(1+ρ)   ⇒  ρ ≤ sin(π/p)/q − 1
```

**这两条都只是必要条件。**（2026-10-21 实测发现）隔了两三层的「叔侄环」会绕回来撞外层，甚至穿进 L0 的管里：

```
最优七级 p=2,q=0.62,ρ=0.26: 最小轴间隙 −0.6217  (L2 vs L0)   ← L2 整只埋进 L0 的管里
三分叉七级 p=3,q=0.50,ρ=0.22: 最小轴间隙 −0.4730  (L6 vs L0)
nb 原版 5,3,4:                最小轴间隙 −0.6875  (L4 vs L3)   ← 原版本来如此
```

正确的写法（本页已实现并在线计算）只需要一个数：

```
自相似下 r(L)=ρ·sU(L) ⇒ 两环间隙 = (sU_i+sU_j)·( d_ij/(sU_i+sU_j) − ρ )
⇒ 全部两两不相交  ⟺  ρ ≤ R* ,  R* = min_{i<j} d_ij/(sU_i+sU_j)
```

`d_ij` 是两条**管轴圆**的最小距离，**只跟 (a,p,q,g) 有关、跟 ρ 无关** ⇒ 结构一改算一次，之后拖 ρ 滑块不用重算。

| p | q=0.50 | 0.53 | 0.56 | 0.59 | 0.62 | 0.65 |
| --- | --- | --- | --- | --- | --- | --- |
| **2** | 0.2000 | 0.1945 | 0.1876 | 0.1794 | **0.1702** | 0.1599 |
| **3** | 0.1272 | 0.0982 | 0.0620 | 0.0240 | 0.0077 | 0.0010 |

两条硬结论：

1. **p=2 时 R\* 与 g 无关**（g=2..7 都是 0.1702）。原因很漂亮：绑定的那一档是
   **所有「隔两级」的环对 L(k+2)/Lk**，它们比值**完全相同**——
   `L2/L0 = L3/L1 = … = L7/L5 = 0.17018`（再下一档「隔三级」= 0.37262）。
   g≥2 这个级别一出现，上限就钉死了。
2. **p=3 时 R\* 随 q 断崖式塌陷**（q=0.56 只剩 0.062、q=0.62 只剩 0.0077）。
   所以「三叉 + 七级 + 互不相交」在几何上就不成立 —— 管只能细到看不见。
   **这就是为什么默认选 p=2。**

### 11.6 页面内的全对复核怎么算的（不卡滑块）

```
for 每个环对 (i,j):
    lb = (|t_i − t_j| − sU_i − sU_j) / (sU_i + sU_j)      ← 球包下界，与 ρ 无关
    if (lb ≥ best) continue                                ← 剪枝（best 用父子对 q/(1+q) 起始）
    取较小的那只圈采样 48 点，用「点到圆」闭式量到较大的圈：
        dist(p, circle) = √( h² + (√(a²+b²) − R)² )
    扣掉采样弓高 R_small(1−cos(π/48)) ⇒ 保守的 d_ij
```

* 点对圆是**闭式**，`O(N)` 不是 `O(N²)`：一对只花 48 次算术，而不是 48×48。
* **分片执行**：每片 ≤ 9 ms（`performance.now()` 计时），用 `setTimeout(...,0)` 让出主线程 ⇒
  3 280 只环、**5 377 560 对**在 ~3 s 内算完，期间滑块照常可拖。
* 结构（a/p/q/g）一改就重算，结果按 `a|p|g|q|mode` 缓存；**拖 ρ 不触发重算**。
* nb 模式不算（管半径恒定，判据不同），直接给「深层 ρ>1 必然重叠」的解析说明。

### 12.2 曲线参数怎么逐级落下去

```js
function curveNK(lv) {
  return (lv === 0) ? [S.nW | 0, S.kW | 0] : [S.nD | 0, S.kD | 0];
}
```

要点：**子环挂的是「父环身上那条曲线」**，所以判断用父环所在层 `lv`：
挂 L1 用 L0 的 (5,1680)，挂 L2 用 L1 的 (1,7)，依此类推（L1…L6 每级都是 (1,7)）。

### 12.3 挂点口径：û₁ 取周向 B，不取法向 N，也不取切线 T

```
P(τ) = t + A·rad + r sinθ·v̂ ,  A = sU + r cosθ ,  rad = cosφ û + sinφ ŵ ,  φ = nτ , θ = kτ
N = cosθ·rad + sinθ·v̂        外法向（管的径向）
B = −sinθ·rad + cosθ·v̂       周向（绕管方向）
子环：t1 = P ,  û1 = sC·B ,  v̂1 = sC·(N×B)   ⇒   ŵ1 = N
```

- **û₁ = B**：p 个子环沿 ±û₁ 铺开。若取 û₁ = N，p=2 时必有一个子环直接落进父管里（实测 Δ = −0.62）。
  取 B 之后，子环中心到父管轴的距离恒为 √(r² + sC²)，与 θ 无关，p 个子环一碗水端平。
- **ŵ₁ = N**：子环的环面贴着父管管壁（法向 = 管的外法向）。**注意这**不是**「把环穿在管上」**
  （那种要让 ŵ₁ 沿切线 T）—— 实测那种穿法会让孙环与自身那一窝重合，比值掉到 0.0066，所以不采用。
  这是按「两种朝向各算一遍、取不重叠的那种」定下来的。

子环的姿态由曲线在该点的**活动标架**定（û₁ = B、ŵ₁ = N）。τ 转一圈，标架自转 k 圈：

- k = 5 时，δ 挪 0.1 rad，标架只转 0.5 圈 → 看起来就是「滑一段」；
- k = 1680 时，δ 挪 0.1 rad，标架已经转了 27 圈 → 子环在原地甩，不是在绕行。

实测（`cap_curve.py phase`，ρ=0.140，12 个相位）：

**绕 L0 轴刚性公转为什么安全**：L0 是绕自己轴（z）旋转不变的曲面。
「把 L1 及以下整体绕 z 转 δ」把整个场景映射成自己的一个**刚体版本** ⇒ 任意两环的中心距、

所以公转途中子环会**暂时离开曲线**，δ=0 时回到曲线上。要核几何、要交静态图，请停在 0°。

### 12.7 观察周期是 360°/p，不是 360°

交付图里那 8 帧按 22.5° 等分，正好铺满一个周期、互不重复（实测两两像素差都 > 1%）。

## 十三、2026-10-21 三次修订：「环轴 ∥ 切线」被证否 —— 与「不切穿父环」几何互斥

### 13.1 起因与结论

老师指出：一键公转时**第二级环的中轴**应当与第一级环面曲线的**切线方向**一致（即环"穿在绳上"）。
我按此实现了 `attach='thread'`（环轴 vh ∥ 切线 T̂，自检残差 **2.5e-16**，精确成立）。
但老师随即指出：**"环面因而近似赤道面，必然切穿父环体。这种情况是错误的，不能让子环切穿上一级环。"**

诚实的结论：**这两条要求在几何上互斥，不是调参能解决的。** 原因见 13.2。

### 13.2 为什么互斥（一句话：T 与 N 严格正交）

- 切线恒在管面的**切平面**内：`N·T = 0` 严格成立（2000 点实测 `max|N·T| = 2.2e-16`）。
- "环不切穿父环"要求环的**平面不与管面相交**，等价于环轴要靠近管面**法向 N**（环面 ≈ 切平面）。
- 于是"环轴 ∥ T"与"不切穿"相差 **整整 90°** —— 一个在切平面内，一个垂直切平面。

取环轴 = T 时，环面必然扫过父管芯圆。用局部二维模型（管截面内的一对同心圆）可得解析间隙

```
Δ = sU·|ρ − q| − ρ·sU·(1 + q)          恒 < 0
```

实测校验（q=0.08, ρ=0.14, sU=5）：公式 `−5×0.08×1.14 = −0.4560`，程序实测 **−0.4560**，逐位吻合。

### 13.3 实测：把 (q, ρ, θ0, ψ) 全扫一遍也救不回来

| 扫描 | 范围 | 最好结果 | 绑定对 |
|---|---|---|---|
| q | 0.08 … 0.62（9 档） | **−0.456** | L0/L1 |
| ρ | 0.02 … 0.80（7 档） | **−0.081** | L0/L5 |
| 自转角 ψ（绕切线） | 0° … 180°，15° 一档 | **−0.431** @150° | L0/L6 |
| 子环挪到管顶 θ0 | 0° … 180°，15° 一档 | **−0.312** @90° | L0/L1 |
| g（层数） | 1 … 6 | g=1 时 **+1.266**（只有一级不穿），g≥2 全为 **−0.925** | L0/L2 |

`ρ→0.02` 仍有 −0.081 ⇒ 不是"管子太胖"，是**芯圆被切**这个拓扑事实。

## 十五、2026-10-21 五次修订：公转轴取错了 —— 必须绕 L0 环的**中轴**（⊥ 环面），不是 z

### 15.2 根因：z 落在 L0 的环面内

本页的环参数式是

```

```

φ 在主圆上扫、θ 绕管扫 ⇒ **环面 = span{uh, wh}，中轴 = vh**。
默认 L0：`uh=[1,0,0]`、`wh=[0,0,1]`、`vh=[0,1,0]`。

我之前的 `rotZLevels()` 把 L1 及以下整体绕 **z** 转。而 z = `wh` 正好**躺在 L0 的环面里**，
所以这不是"绕着环转"，而是"让子树在环面内扫过环体"—— 子环必然从 L0 的管里穿过去。

改成绕 `vh`（= L0 环的中轴，垂直于环面）后：L0 环面对自身中轴旋转不变 ⇒ 整个场景被
**刚体**映射成自己 ⇒ 任何环对的距离一个字都不变。

## 十六、`anu3级螺旋*.py` 里的 B/N/T 关系（学习记录）

来源：`E:/pythonProject/分形mandelbrot/anu3级螺旋 正确.py`（`calculate_spiral_coords` / `sweep_level1`，第 44–95 行）。

### 16.1 三面架怎么建

```python
T = r'(t) / |r'(t)|                    # 单位切线
N = r''(t) / |r''(t)|                  # ← 直接取二阶导方向，没扣切向分量
B = (T × N) / |T × N|                  # 副法向
```

子级扫掠：

```python
vector = R1 * (cos(twist * t) * N + sin(twist * t) * B)
P_child = P_L0 + vector
```

⇒ **缠绕面 = span{N, B}，子级的轴 = 该面的法向**；θ = twist·t 保证"父级每走一匝、子级绕一匝"。

### 16.2 原式的一处偏差（实测）

`N = r''/|r''|` 在**速度不均匀**的曲线上并不与 T 正交（r'' = v'T + v²κN′ 含切向分量）。
用原脚本参数（k=2401, m=0.66, a=1, b=1.414, c=0.75, d=7）在 200000 点上实测：

| 量 | 数值 |
|---|---|
| max \|T·N\| | **0.322003** → 倾角 **18.8°** |
| mean \|T·N\| | 0.130 → 7.5° |
| 子级实际轴 N×B 与切线的夹角 | 均值 ≈ 8.9°，最大 18.8° |

修正只需一步 Gram-Schmidt：`N ← norm(r'' − (r''·T)T)`，修正后 max |T·N| = **3.2e-16**，
缠绕面严格 ⊥ T，子级轴与切线逐点重合。

### 16.3 半径：这两个脚本的比例不是最优

- `anu3级螺旋 正确.py`：`R0=2401, R1=49, R2=1` ⇒ 级比 1/49 = 0.0204
- `anu3级螺旋.py`：`R0=1680, R1=1680/7, R2=1680/49` ⇒ 级比 1/7 = 0.1429

几何自洽的比例只有一个 —— **子级直径 = 父级匝距**（相邻匝相切、不穿）：

```
r(子) = 父级匝距 / 2,   级比 = √(1+π²)/7 = 0.4709869014
```

推导：父级匝距 p ⇒ r=p/2 ⇒ 子级一匝长 = √(p² + (2πr)²) = p√(1+π²) ⇒ 子级匝距 = p√(1+π²)/7。
与 §14 里 Anu 引擎（`fill·pitch/2`）实测的 0.4709869013536593 逐位一致。

### 16.4 只有 3 级的原因

`sweep_level2()` 用的是 `N_unit_L1, B_unit_L1` —— 那是**父曲线 L0** 的标架（`calculate_spiral_coords`
对 `t_spiral1` 求的），不是 L1 自己的标架，而且第 3 级只撒了 `sub_n` 个点、没连成螺旋。
要往后推到 7 级，必须**对子级曲线本身再求一次 Frenet 标架**，这才是递归能继续的前提。

## 十七、逐级公转：每一级绕「自己父环的中轴」（2026-10-21）

### 17.1 从「整树绕 L0」改成「逐级递归」

`§15` 的做法是**整棵子树绕 L0 的中轴**做一次刚体旋转 —— 只有第 1 级在动，深层只是被拖着走，
没有体现「子环也绕上一级转」。本版换成真正的递归：

```
walk(节点 i):
    对 i 的每个子环 c:
        把 c 连同它下面整棵子树，绕「父环 i 的中心 t_i + 中轴 vh_i」整体转 φ_i   ← 刚体
        walk(c)                     # c 已定，c.vh 已更新，供 c 的子环用
```

- 转角是**相对父环**的：L1 转 φ、L2 相对 L1 转 mix·φ、L3 相对 L2 转 mix²·φ……
- 绝对转角逐级累加：`φ, φ(1+mix), φ(1+mix+mix²), …` —— 一台**逐级减速的齿轮组**；
  `mix=1` 时就是 φ, 2φ, 3φ…
- 旋转中心必须取**父环的中心**（不是原点）。§15 里 L0.t 恰在原点，所以两者数值相同；
  L2 绕 L1 时 L1.t ≠ 0，漏掉中心会整层错位。

实现里两处坑：

1. 递归里的循环变量必须**局部**（`for (var j …)`）。写成外层 `var j` 时，递归返回后
   外层 j 已被内层顶到 `C.length`，**第二棵子树根本不转** —— 实测表现为两只 L1 完全重合在一点（Δ = −2r）。
2. 子树在 pre-order 数组里是**连续区间** `[i, sub[i])`，`sub[i]` 取最后一个子节点的 `sub`。

### 17.2 为什么父子永远不会互穿

环面绕自身中轴旋转不变 —— 绕父环的 `vh` 转 φ，父环的**曲面映射到自己**。
所以子环（中心在父环面上）转完之后仍然落在父环面上，只是换了个 φ 位置：
**几何上等价于「子环贴着父环的环面滑行」**，姿态也跟着 `vh` 一起转，始终贴壁。

父子之间因此只做**刚体相对转动** ⇒ 父子间隙逐字不变。

### 17.3 硬边界：摆幅有上限（这是几何，不是分辨率）

L1 的环面与 L0 的**管面相切**（贴壁挂法的必然结果）。子环沿父环面滑行时，
一定会经过那个切点 —— 到那里它就撞上祖父。

实测（g=6、127 环、8001 对、25 个相位，q=0.62）：

| 管径 ρ | L2 相对父环的安全摆幅 | 该处余量 |
|---|---|---|
| 0.14（§13 的最优值） | **±16°** | +0.0325 |
| 0.08 | ±25° | +0.068 |
| 0.06 | ±60° | +0.091 |
| 0.05 | ±68° | +0.438（起点） |

`amp × mix × ρ` 实测矩阵（✓ = 全相位 Δmin > 0）：

| ρ | amp=15° | amp=45° | amp=90° | amp=180°（整圈） |
|---|---|---|---|---|
| 0.14 | mix≤0.5 ✓ / mix1 ✗−0.30 | ✗−0.27 | ✗−0.69 | ✗−0.93 |
| 0.08 | mix≤0.7 ✓ | mix≤0.5 ✓ | mix≤0.3 ✓ | mix ≤0.3 ✓(+0.063) |
| 0.06 | 全部 ✓ | mix≤0.7 ✓(+0.086) | mix=0.5 ✓(+0.103) | ✗ |
| 0.05 | 全部 ✓ | 全部 ✓ | mix≤0.5 ✓(+0.103) | mix≤0.3 ✓ |

结论：**ρ=0.14 那种「紧贴到只余 0.008」的参数，深级几乎不允许运动**（L2 只有 ±16°）。
要让「逐级公转」看得见，必须把管径放细，把余量让给运动。

### 18.1 病灶有两处，不是一个

1. **取景按外接球算**：`scale = min(W,H)·(1−2·PAD)/(2R)`，`R` 是「所有环心到场景中心的最远距离 + sU + r」。
   外接球在正交投影下永远给出**正方形包围框**，而环套环是扁的（投影宽高比约 1.6），
   一宽屏就全是空边 —— 实测图形只用到画布的 **60%**。
2. **画布被「一屏放得下」压死**：`mainMaxH()` 减掉顶栏、说明段落、图例、指标表之后只剩 200 出头，
   窗口一矮（如 1080×470）画布就只有 **314×220**，图上什么都看不清。

### 18.2 改法一：按「真实投影包围盒」取景

把每只环的**外沿圆**（`t + (sU+r)(cos a·uh + sin a·wh)`，各取 24 点）投影到相机平面，
量出屏幕上的 x/y 真实跨度 `bw, bh`，再：

```
scale = min( W·(1−2·PAD)/bw , H·(1−2·PAD)/bh ) · zom
```

同时把包围盒中心平移到画布正中（正交下沿 s/u 平移 eye 与 target 不改变视线方向）。
`PAD` 从 0.075 收紧到 **0.05**（包围盒已经很紧，5% 边距够）。

实测（g=6 默认参数，1920×1080 内联画布 877×614）：图形横向占 **89.9%**、上下留白 44 px，正好等于 5%。

> 校验方法：数画布最外 2 px 里的非背景像素（「贴边像素」）。9 种视角/参数组合
> （g=6/g=7/穿线 thread/g=0/无曲线 nb 原式/pit=85°/pit=90°）**全部为 0** —— 不切边；
> 只有用户自己把 `zom` 拉到 1.6 时才允许出框（那是「放大看局部」，本来就该出框）。

### 18.3 改法二：内联放不下就自动铺满整屏

```
autoFill():
    need = max(420, 视口高 × 0.45)
    若 视口高 ≥ 320 且「内联能给出的画布高度」< need  ⇒  自动进全屏
```

- **内联**：窗口够高时保持原样（右侧参数栏、说明、图例都在），画布吃掉剩余高度。
- **全屏**：`#cardMain` 变 `position:fixed; inset:0`；标题行浮到**右上角**（半透明 .55，悬停才实），
  把整屏高度让给画布；画布**不再守 500×350**，改用窗口比例 —— 因为取景已按包围盒算，
  改比例不会拉伸图形，宽屏里高度才能真正用满。
- **退出**：点「✕ 退出全屏」或按 Esc ⇒ 记 `AUTO.veto = true`，之后**不再自动进**（尊重用户选择）；
  手动点「⛶ 全屏」会清掉 veto，自动逻辑恢复。

实测（同一页面，deviceMetrics 切换）：

|---|---|---|---|

## 十九、ρ 的下限取 1/137（精细结构常数 α）（2026-10-21）

### 19.1 为什么是 1/137

`ρ = r/R`（每级管半径 ÷ 本级主半径，逐级自相似）。本页原来把滑块限制在 **0.06–0.42**，
是出于「环还得看得见」的直觉；但数学上 `ρ` 可以一直小下去，唯一的硬约束只有三条：

```
① 父子      ρ ≤ q/(1+q)
② 兄弟      ρ ≤ sin(π/p)/q − 1
③ 全对      ρ ≤ 0.1495（逐级挂曲线后的实测上限）
```

它们全是**上限**，没有下限。把滑块下限压到 **1/137 = 0.00729927…**（精细结构常数 α），
是本页能给出的最细一档：几何仍然成立，而屏幕上刚好退成「一根丝」。

### 19.2 细到什么程度（实测，g=6 / q=0.62 / 127 环）

| ρ | 1/ρ | L0 管半径 | 静止全对 Δmin | 面片数 | 单帧（无头无 GPU） |
|---|---|---|---|---|---|
| 0.140 | 7.1 | 0.700 | +0.007751 | 21736 | 152 ms |
| 0.100 | 10.0 | 0.500 | +0.045734 | — | — |
| 0.060 | 16.7 | 0.300 | +0.091769 | 16736 | 87 ms |
| 0.030 | 33.3 | 0.150 | +0.131164 | — | — |
| 0.014 | 71.4 | 0.070 | +0.153652 | — | — |
| **1/137** | **137.0** | **0.0365** | **+0.163341** | 15744 | 79 ms |
| 0.005 | 200 | 0.025 | +0.166701 | — | — |

ρ 越小，**每一对环之间的余量反而越大**（管子细了），所以静止永远安全 ——
1/137 时的余量 0.1633 是 L0 管半径（0.0365）的 **4.5 倍**。
同时面片数按 `K = 管截面周长/9` 自动降档，**细管比粗管更省**（152 → 79 ms）。

### 19.3 关键结论：α 细丝 + 整圈公转可以真的转满 360°

之前 §17 的结论是「整圈在任何 q/ρ 下都穿」。那只对 **mix = 1**（每级同幅）成立。
细管把余量让出来之后，只要**级间倍率**收得够小，整圈就能走完：

| ρ | amp | mix | Δmin | 结论 |
|---|---|---|---|---|
| 0.140 | ±180° | 1 | −0.925 | ✗ |
| 0.060 | ±180° | 1 | −0.344 | ✗ |
| 1/137 | ±180° | 1 | −0.0424 | ✗（L0/L3） |
| 1/137 | ±90° | 1 | −0.0424 | ✗ |
| 1/137 | ±60° | 1 | **+0.0186** | ✓ |
| 1/137 | ±180° | 0.45 | **+0.0799** | ✓ |
| 1/137 | ±180° | **0.40** | **+0.163168** | ✓ 推荐 |
| 1/137 | ±180° | 0.50 | −0.0281 | ✗（**两只同级 L2** 撞在一起） |

注意瓶颈换了：**不再是父子**（父子永远不穿），而是**不同父的同级兄弟**。
原因：每个 L2 绕的是**自己那只 L1 的中轴**，而各 L1 的中轴朝向不同，
mix 一大，相邻子树里的同级环就会在中途碰头。

`q` 也有最优区：α 细丝下 q=0.62 最松（+0.1633），q=0.70 反而穿（−0.0111，同级 L4/L5）——
因为兄弟约束 ② 被违反了。

- 「↻ 一键公转」卡新增按钮 **⚛ α 细丝 · 整圈公转（mix=0.4）**，一键设参并直接开转。

## 二十、ρ = 1/137 是临界值吗？—— 以及 α 能不能从这个结构「涌现」（2026-10-21）

### 20.1 先纠正我在上一轮说错的两处

| 我上一轮的说法 | 实测 | 错在哪 |
|---|---|---|
| 「ρ 压到 1/137 才能整圈，这是个特殊临界」 | 1/33、1/137、1/200 三档的可行域**逐格相同** | 只测了 0.45 / 0.5 两个 mix，把「恰好够细」当成了临界 |
| 「mix = 0.5 时中心线相切」 | 临界在 **mix ≈ 0.47**，且**随 q 变** | 采样不足（13 相位），且 mix ≥ 0.48 后 Δmin 不再变深，是相交不是相切 |

这两处都是**采样密度不够**造成的误判。教训写在 §20.4 末尾。

### 20.2 可行域是一整片，不是一个点

g=6（127 环）· q=0.62 · 每级摆幅 ±180°（真整圈）· **25 个相位** · 记录全对最小间隙：

| 7（ρ=0.14） | ✗−0.31 | ✗−0.83 | ✗−0.83 | ✗−0.85 | ✗−0.89 | ✗−0.93 | ✗−0.93 | ✗−0.93 |

**1/137 那一行与 1/33、1/200 两行的 √/× 图案逐格相同。** 137 落在可行域**内部**，
上面还有 1/500、1/1000 更好 —— 它只是「细到屏幕上只剩一根丝」的一个好看刻度，不是边界。

### 20.3 ρ → 0 的极限：真正的临界在 mix ≈ 0.47

把管子细到几乎为零，Δmin 里「管壁」那一项消失，只剩**中心线之间的距离** Δ_c(mix)：

| mix − s | Δmin（ρ=0.002） | ρ=0.001 | ρ=0.0005 | 解读 |
|---|---|---|---|---|
| −0.006 | +0.016688 | +0.016695 | +0.016698 | 三档**完全相同** ⇒ 纯中心线间距 |
| −0.003 | +0.006728 | +0.006741 | +0.006747 | 同上 |
| −0.0005 | −0.000893 | −0.000876 | −0.000867 | 已经相交（极浅） |
| ±0 | −0.002343 | −0.002325 | −0.001922 | 进入管壁项 |
| +0.006 | −0.007688 | −0.003844 | −0.001922 | 按 ρ 线性分层 |

两条互补的规律：

- **正侧**（mix < 0.47）：Δmin 与 ρ 无关 —— 是中心线在几何上的净间距；
- **负侧**（mix ≥ 0.48）：Δmin = **−3.844·ρ**（精确线性）且**不再随 mix 变深** ——
  说明那两只 L2 的**中心线已经相交**，剩下的是管壁互穿的固定深度。

所以「能不能转整圈」由**两道独立的门槛**决定：

```
mix  ≤ 0.47          ← 中心线不能相交（与 ρ 无关的硬边界）
ρ    ≤ ρ_crit(mix)   ← 中心线有余量时，管子不能比余量粗
```

### 20.4 mix 的临界不是常数，也不是级比

在 ρ = 0.001（管子几乎为零）下用两分法求 mix_c（25 相位）：

| 参数 | mix_c | 与 s = 0.47099 比 |
|---|---|---|
| p=2, q=0.50 | **0.5594** | 差 +0.088 |
| p=2, q=0.58 | **0.5594** | 差 +0.088 |
| p=2, q=0.62 | **0.4706** | 差 −0.0004（0.08%） |
| p=2, q=0.64 | **0.4019** | 差 −0.069 |
| p=3, q=0.50 | **0.5990** | — |

q=0.62 时 mix_c 恰好贴近级比 s = √(1+π²)/7 = 0.470987，**差 0.08%** —— 很诱人，
但 q=0.50 时是 0.5594、q=0.64 时是 0.4019，**同一结构换个 q 就差 40%**。
所以它不是「结构常数」，只是 (p, q) 的函数。q=0.50 与 q=0.58 给出同一个 0.5594，
说明瓶颈在两张不同的「最近对」之间切换，不是一个解析式的根。

> **方法教训**：13 个相位（步 30°）会把 ρ=0.06、mix=0.45 这种边界点判成 ✓，25 相位判成 ✗。
> 临界附近的符号必须 ≥ 25 相位，最好 49；边界值本身有 ±0.01 的不确定度。

### 20.5 α 在这个结构的代数闭包里凑不出来

结构里**不靠外部输入**的无量纲量只有：

```
π = 3.141592654
S = √(1+π²) = 3.296908309      （一匝螺旋的弧长比）
s = S/7     = 0.470986901      （级比，逐级自相似的核心）
整数：p=2, 7（每级匝数）, 1680（L0 匝数）, 5（nW）, 6（层数）
```

用 {π, S, s, 7, 2, 5, 6, 1680} 做**三因子、半整数幂**的全枚举
（8³ × 8³ = 262 144 个表达式），在相对容差 1e-4 内命中 137.035999：

| 目标 | 命中数（容差 1e-4） |
|---|---|
| **137.035999（α⁻¹）** | **0** |
| 137.5（无意义对照） | 0 |
| 200.0（无意义对照） | 15 |

最接近 137.036 的是 `S·2^1.5·6^1.5 = 137.0499`，差 1.0e-4 —— 而这需要**挑**指数 1.5，
不是结构给的。结论：**α⁻¹ 不在这个结构的代数闭包里**。

反过来问「若 α = F(s)，F 该是什么」：幂律要求 `s^x = 1/137.036` ⇒ **x = 6.5348**。
它不是 g=6、不是 13/2、不是 7，没有任何几何理由取这个指数。

唯一的「近亲」：`1/s^6 × 1.5 = 137.42`（差 0.28%）、`4π³+π²+π = 137.0363`（差 2.2e-6）。
后者与本结构无关（任何含 π 的地方都能写），见 §20.6。

### 20.6 历史上那些「导出 137」的公式，以及三条判据

| 尝试 | 数值 | 结局 |
|---|---|---|
| Eddington (1929–1939) | 先是 1/136，测到 137 后改口 1/137 | 后来被他学生叫「Adding-one」；纯事后拟合 |
| Wyler (1969) | (9/8π⁴)(π⁵/2⁴5!)^(1/4) ≈ 1/137.03608 | 精度 1e-6，但缺物理动机、因子任意挑选，公认是巧合 |
| Gilson / 4π³+π²+π | 137.036304 | 差 2.2e-6，极其惊人，但**无机制** |

我把 4π³+π²+π 放进同一套统计里检验：枚举 aπ³+bπ²+cπ+d（系数 −4…4），
落在 100–200 之间的表达式有 **932 个**，其中落在 137.036 ± 0.001 内的只有 **1 个**，
而随机期望是 0.02 个 —— 也就是说它确实「罕见 50 倍」，**比随机好得多**。
但「罕见」不等于「有原因」。

三条可操作的判据（缺一不可）：

1. **无自由参数**：公式里的每个系数、指数都必须由结构本身给出，不能挑。
2. **唯一性**：结构稍变（p、q、g 换一下）结论必须仍然成立；如果换个参数就散架，那是拟合。
3. **必须给出跑动**：α 在 m_Z ≈ 91 GeV 处是 **1/127.95**，不是 1/137。
   纯几何常数是「不跑」的 —— 只对上低能值、解释不了 1/128 的，一定是拟合。

用这三条打分：Eddington ✗✗✗、Wyler ✗✗✗、4π³+π²+π ✗✗✗、本结构（凑不出，无从谈起）。

### 20.7 和乐检验：唯一「物理上可能承载 α」的位置，也没有

α 在规范理论里就是相位/和乐，所以如果这个结构能产生 α，最可能出现在「沿闭合曲线绕一圈、
标架转过的角度」里。实测各级环面法向 vh 与下一级的夹角：

```
kW=1680 kD=7  q=0.62 g=6   L0→L1:90.000  L1→L2:90.000 … L5→L6:90.000
kW=336  kD=7  q=0.62 g=6   全部 90.000
kW=840  kD=7  q=0.62 g=6   全部 90.000
kW=1680 kD=7  q=0.50 g=6   全部 90.000
kW=1680 kD=14 q=0.62 g=6   全部 90.000
```

换 k（绕行匝数）、换 q、换 kD、换层数，**都是精确 90.000°**。
说明这个结构在数学上是**严格正交**的（曲率与挠率正交），没有任何几何相位漏出来。

对照：α = 0.0072974 rad = **0.4181°**，2πα = **0.0459°**。结构里没有这两个量。

### 20.8 要让 α 真的「涌现」，数学上还缺三件东西

1. **作用量**。结构现在只给「长度比」。α 的物理定义是 e²/(4πε₀ħc)，是一个**耦合强度**，
   必须从某个场的作用量里算出来（例如把七级螺旋当成 U(1) 联络的经典解，
   由解的模空间度量给出有效作用量）。目前完全没有这一步。
2. **跑动**。见判据 3。要给出 β 函数，而不只是一个数。
3. **一条能算的链**，从 (p, 7, g) 到 α⁻¹，中间不许插任何手调系数。

现在的状态是：结构本身很美（s = √(1+π²)/7 精确到 2.5e-16），但它是**运动学**的美，
不含任何**动力学**信息。α 是动力学量。

### 20.9 顺带：q ≈ 0.62 也不是黄金比

ρ=1/137、mix=0.4、整圈下扫 q：

| q | 0.59 | 0.61 | **0.618019** | 0.62 | **0.63** | 0.64 | 0.642 | 0.65 |
|---|---|---|---|---|---|---|---|---|
| Δmin | +0.138 | +0.155 | **+0.161** | +0.163 | **+0.172** | +0.016 | ✗−0.027 | ✗−0.031 |

- 最好的是 **0.63**（+0.172），不是 0.618；
- 1/φ = 0.618019 的余量是 0.161，比 0.63 低 6%，比 0.62 低 1%；
- 真正的上限是 **q_crit ≈ 0.6405**（0.64 尚可 +0.016，0.642 就穿），
  而这个上限**依赖 mix**（mix 小则 q 可更大）——所以它也不是结构的常数。

`1/φ` 与 `0.62` 的接近是「0.6 附近本来就是好区」的必然结果：最优平台横跨 0.60–0.63，
黄金比恰好落在平台边上。这跟 137 落在可行域内部是同一类巧合。

## 二十一、两套新方案（p=7 / L0=240·八层）能涌现 α 吗（2026-10-21）

> 老师提的两条：**① 把 nb 的 p（每环数）调到 7，重新考虑 q 与 ρ；② 把 L0 匝数 1680 改成 240，
> 层数加到 L0–L7**。两条都做了实测。**结论先给：都不涌现**，而且这次拿到了比"没命中"更硬的证据。

### 21.1 方案一：p=7 之后，q 到底被什么钉住

**先纠正一条本页自己写过的公式**。参数区原来写「兄弟 `ρ ≤ sin(π/p)/q − 1`」，
按它 p=7、ρ=0.06 时 q 只能到 **0.41**。**这条只对「挂主圆」成立**：
挂曲线时子环的环面不在极向平面里，兄弟之间是**错位穿插**的，实际能大得多。

用页面自己的 `pairGap()`（管轴圆最近距 − 两个管半径）逐点扫，`attach='curve'`、L0–L3（400 环）：

| q | 0.44 | 0.45 | 0.46 | 0.47 | 0.48 | **0.49** |
|---|---|---|---|---|---|---|
| Δmin（ρ=1e-4） | +0.5507 | +0.4198 | +0.2869 | +0.1520 | +0.0152 | **−0.0002** |
| Δmin（ρ=0.06） | +0.1321 | −0.0381 | +0.0264 | +0.0046 | +0.0154 | **−0.1318** |

- **q 的硬上限 ≈ 0.489**（ρ→0）：绑定点是 **L2 兄弟的中轴圆相交**（Δmin 塌到 −2r，正是两管相切穿透的特征量）。
- ρ=0.06 时 0.45 就被 L2–L3 咬掉 0.038，0.46–0.47 又有窄窗能过 —— 工程上取 **q=0.42**（**跨层全配** Δmin +0.242；
  页面面板显示的 0.3704 是它自己「父-子 + 同级前两只」的分级口径，不含跨层远亲对，所以偏乐观）。
- **p=2 那套 q=0.62 在 p=7 下直接作废**（q=0.49 就穿，q=0.62 深穿 −0.13 以上）。

**q 上限还随层数走**（ρ=0.06，实测）：

| p | g=1 | g=2 | g=3 |
|---|---|---|---|
| 2 | 1.00 | 0.841 | 0.841 |
| 3 | — | 0.671 | 0.534 |
| **7** | **0.931** | **0.481** | **0.448** |

⇒ **q 不是结构的常数**：换 p、换层数、换 ρ 都能把它挪。想拿"某个 q 刚好等于某常数"当结构证据，先得解释为什么是这个 g。

> ⚠ **踩过的坑，写下来免得再犯**：`gap(q)` 在这套几何里**非单调**（0.45 咬、0.46 又不咬），
> 因为它取的是全对最小值，绑定的那一对会随 q 换。我第一次用二分法求 q_crit，得到 **0.4711**，
> 跟 s = √(1+π²)/7 = **0.470987** 差 0.03%，差点当成"结构自己选出 s"报上去；
> 逐点扫才发现真边界是 0.489，那个 0.4711 纯粹是**非单调函数上的二分假象**。
> 教训与 §20 相同：**临界值必须扫，不能二分**。

### 21.2 方案二：L0 1680→240、加到 L0–L7

- 240 = 1680/7，所以这条改动的实质是把「1680」从 L0 **挪到 L1**（240×7=1680），多出的一层只是再乘 7。
- p=7、8 层：环数 `1+7+…+7⁷ =` **960 800**（渲染不了，只能算数）；
- p=2、8 层：**255 环**（可渲染，已做成预设 ⑧，ρ=0.10 时 Δmin **+0.028**）。
- 结构上新增的**数**只有两个：**240** 与 **960 800**。

### 21.3 α 枚举：这次用"零分布"判定，而不是"有没有命中"

穷举三因子半整数幂 `∏ bᵢ^eᵢ`（e ∈ ±0.5…±3），**逐个**结构量集合跑：

| 集合 | 表达式数 | α⁻¹ 最近的式子 | 相对误差 | 随机靶值中位误差 | 比 α 更近的随机数占比 |
|---|---|---|---|---|---|
| 方案一 p=7（9 个量） | 145 152 | `π³·2^-2.5·5² = 137.0297` | 4.6e-5 | 9.3e-5 | **29.1%** |
| 方案二 240/八层（12 个量） | 380 160 | 同上 | 4.6e-5 | 6.3e-5 | **39.4%** |
| 旧集 p=2（8 个量） | 96 768 | 同上 | 4.6e-5 | 1.07e-4 | 26.4% |

怎么读这张表：

1. **α 根本不算"特别难凑"**。在 [50,300] 里随便挑 2000 个数，中位误差就是 1e-4 量级；
   方案一里 **52% 的随机数**都能被凑进 1e-4 相对精度，方案二里是 **67%**。
   α 排在 29%/39% —— 也就是**比它更不像**的随机数一大把。
2. 那个"最接近的式子"**不含任何结构量**：`π³·2^-2.5·5²`，p、7、1680、240、环数一个都没用上。
   结构加进去只是让分母变多，没让它更近。
3. 要求 **±1e-4 绝对误差**（即 7 位有效数字）时：两套**都是 0 命中**。
   但 α 的实验精度是 **±2×10⁻⁸**（CODATA 137.035999084(21)）——
   要"导出 α"得对到 8 位，这里连 4 位都差着。

### 21.4 真正"像"的两个整数，以及它们为什么不算

| 结构 | 环数 | 除以 10^k | 与目标差 |
|---|---|---|---|
| p=7、L0–L6（7 层） | **137 257** | 137.257 | vs α⁻¹=137.036 → **+0.161%** |
| p=2、L0–L6（7 层） | **127** | 127 | vs α⁻¹(m_Z)=127.95 → −0.74% |

这两个数字确实好看，但：

- **十年（÷1000）是白送的自由度**。把 `(p^{g+1}−1)/(p−1)` 全族（p=2…8、g=1…8）各乘 10^k（k=−3…3）
  一共 **392 个候选**。随机分布下，命中 137.036±0.2% 的**期望个数是 0.68**，
   即「**至少出现一个这种 '137.x' 的概率约 49%**」。实测正好出现 **1 个**（就是 137 257）。
   **一半概率的事，不能当证据。**
- **加减一层就崩**：137 257 的上一层是 19 608、下一层是 960 800。要它"等于 α"，
  得先说明为什么"7 层"是神圣的 —— 而 1680 本身在 Anu 体系里也不是从 7 层算出来的。
- **两个能标各挑一个整数**：127 对 m_Z、137.257 对低能，都是事后挑的。同一结构给不出两个值。
- **精度**：137.257 与 137.036 差 **0.16%**，是 α 实验精度的 **160 万倍**。

### 21.5 结论

| 判据 | 方案一 p=7 | 方案二 240/八层 |
|---|---|---|
| 无自由参数 | ✗ q 仍自由（0.30–0.489）、ρ 完全自由 | ✗ 同左，另加"几层"也自由 |
| 唯一性（换参数不散架） | ✗ g=6→7 环数从 137 257 变 960 800 | ✗ 240 只是 1680/7 |
| 必须给 β 跑动 | ✗ 静态自相似结构没有能标 | ✗ 同左 |

**一句话**：p 调到 7、加一层、把 1680 挪到 L1，都只改变了"数数的结果"，
没有给结构增加**动力学**。α 是耦合强度，它的数值来自作用量与重整化；
一个纯几何、标度自相似的嵌套结构里没有这两个东西，
所以**再怎么加层、加分支，也只会得到更多"看起来像"的整数**。

真要让它"涌现"，缺的是这三样（缺一不可）：

1. **一个作用量**：得有场、有荷、有 ħ，才能定义 e²/4πε₀ħc；
2. **能标依赖**：结构必须自己带一个长度/能量标度（自相似结构恰恰**没有**能标）；
3. **唯一性**：q、ρ、g 必须被几何**唯一**选出来（例如"双切点"条件），而不是像现在这样留一条带。

### 21.6 本轮页面改动

- **p 上限 5 → 7**（滑杆/数字框/绑定范围三处同步）；
- 新增预设 **⑦ p=7 · 每环 7 个（400 环）**：p=7, g=3, q=0.42, ρ=0.06 → 跨层全配 Δmin **+0.242**；
- 新增预设 **⑧ L0=240 · 八层**：p=2, g=7, kW=240, q=0.62, ρ=0.10 → 255 环，实测 Δmin **+0.028**；
- 参数区补一条 `p7Note`：写明 sin(π/p)/q−1 只对挂主圆成立、p=7 的实测上限 0.489/0.44、
  以及"gap(q) 非单调，别二分"。

## 二十二、「左右晃」的两个真凶：sin 往复 + 相机每帧重算（2026-10-21）

> 老师原话：「点『逐级公转演示』还是出现左右晃……看起来次级环绕 L0 环**左转 1/4 圈，然后右转 1/4 圈**，
> 为何不是一致朝同一个方向顺时针绕或逆时针绕？」
>
> 是**两个独立毛病**叠在一起，而且第二个比第一个影响大得多。

### 22.1 真凶一：相位是 sin 往复（这就是「左转再右转」）

`revAngle()` 有两档语义，之前一直被混着用：

```js
function revAngle() {
  var A = (S.revAmp === undefined ? 180 : S.revAmp);
  if (A >= 179.5) return S.revPh;                       // 整圈：单调
  return (A * Math.PI / 180) * Math.sin(S.revPh);       // 限幅：sin 往复
}
```

旧演示预设给的是 **`revAmp: 45`**，于是相位走 `45°·sin(t)`：

| 时间 | φ | 实际转角 |
|---|---|---|
| 0 | 0 | 0° |
| T/4 | π/2 | **+45°**（向右 1/8 圈） |
| T/2 | π | 0° |
| 3T/4 | 3π/2 | **−45°**（向左 1/8 圈） |

**永远是「过去再回来」，不可能同向绕。** 这不是渲染问题，是这条式子的定义。

**改法**：演示预设改 **`revAmp: 180`（整圈）+ `revMix: 0.12`**，`revAngle()` 走单调分支，
φ 从 0 一直涨 ⇒ **每一级都朝同一个方向转**，只是转速逐级递减：

| 层 | 相对父环转角（L1 转满 360° 时） | 绝对累计 |
|---|---|---|
| L1 | **360°** | 360° |
| L2 | 43.2° | 403.2° |
| L3 | 5.2° | 408.4° |
| L4 | 0.6° | 409.0° |
| L5 | 0.07° | 409.1° |
| L6 | 0.008° | 409.1° |

倍率全为正 ⇒ 方向一致；倍率递减 ⇒ 一台**逐级减速的齿轮组**。

### 22.2 真凶二：相机每帧按「当前帧」重算包围盒（这才是「晃」的主因）

`camFor()` 的取景是「量当前场景的投影包围盒 → 定 scale → 把包围盒中心挪到画布中心」。
静止时没问题，但公转时**形状每帧都在变**，于是：

- `scale` 每帧变 ⇒ **整幅图跟着缩放**；
- `center` 每帧变 ⇒ **整幅图跟着平移**。

实测（1200×770，整圈 24 相位，ρ=0.06、mix=0.12 的演示结构）：

| 做法 | scale 范围 | 抖动幅度 |
|---|---|---|
| 每帧重算（旧） | 40.246 … 68.092 | **69.19%**（mix=0.20 时 73.67%） |
| 全程并集锁定（新） | 40.098（恒定） | **0.00%** |

**近 70% 的缩放抖动**——图形自己只转几度，画框却放大又缩小近一倍，观感就是「晃」，
而且会误以为环在前后摆动。旧 demo 里 `±45°` 只是让这个抖动更明显，不是根因。

**改法**：新增 `camLock(W,H)`。开转前把**整个行程上 16 个相位**的包围盒求并集，
锁成一台固定相机，公转全程复用：

```js
if (S.rev) {
  if (!CAMLOCK || CAMLOCK.W !== wh[0] || CAMLOCK.H !== wh[1]) camLock(wh[0], wh[1]);
  cam = CAMLOCK.cam;
} else {
  cam = camFor(wh[0], wh[1], sc);          // 静止时仍是「量体裁衣」
}
```

- 整圈档取 φ = 0, 2π/16, …, 15·2π/16；
- 限幅档（`revAmp<180`）只取 −A…+A 那一段（`sin` 走的就是这段），不会白留空边；
- 参数一变（`afterParam`）就 `camUnlock()`，下一帧按新参数重锁；全屏/改尺寸靠 `W/H` 不匹配自动重锁。

**验收（headless CDP，真实点按钮）**：

| 指标 | 实测 |
|---|---|
| 相机 scale（8 帧连续播放） | **44.400 / 44.400 / … 恒定**（mix=0.20 时同值） |
| 画面像素覆盖率 | 7.00% – 7.32%（不呼吸） |
| 相位 | 26.2° → 44.3° → 54.3° → … → 115.5° **单调** |
| L1 环心世界坐标 | 连续变化，无跳变 |
| JS 错误 | 无 |

代价：画面比「只按当前帧取景」小一圈——因为要装下**整个行程**最伸出的姿态。
这是「不晃 + 不切边」的必然代价，要更大就用缩放滑杆（`zom`）或全屏。

### 22.3 顺带修掉的第三个坑：`mix<1` 的整圈**不能把相位取模**

旧 `tick()` 里 φ 一到 `2π` 就 `-= 2π`。`mix=1` 时没事（每级都转满整圈、各自回位）；
但 `mix=0.12` 时 **L1 回原位、L2 只相对转了 43.2°**，相位一归零 ⇒ 深层环**瞬移 43.2°**，看起来就是跳帧。

改法：整圈档让 `revPh` 一直增长（`L1` 每圈回位、深层持续同向**进动**），
只有限幅档（`sin`，真的有 `2π` 周期）才取模。进度条用 `revPh % 2π` 显示。

> 这也是这个结构的一个真结论：**`mix<1` 的逐级公转没有整体周期**，只有 L1 的周期。
> 深层在 L1 转一圈后同向多走了 `mix·360°`，永远不回到出发点 —— 是进动，不是振荡。

### 22.4 整圈的行程上限：`mix` 到底能到多少

`ρ=0.06、p=2、q=0.62`，36 相位 × 全对（8001 对）实测 min gap：

| mix | g=4 | g=5 | g=6 | 判定 |
|---|---|---|---|---|
| **0.12** | **+0.2387** | **+0.1480** | **+0.0918** | ✓ **采用值** |
| 0.16 | +0.2387 | +0.1480 | +0.0918 | ✓ 与本底同值 |
| 0.20 | +0.2387 | +0.1480 | +0.0918 | ✓ 也合法（L2 转 72°，后半程画面偏乱） |
| 0.22 | +0.2203 | +0.1480 | +0.0918 | ✓ 边缘 |
| 0.24 | +0.0104 | +0.0104 | +0.0104 | △ L2 兄弟中轴圆相切 |
| 0.26 | −0.0451 | −0.0451 | −0.0451 | ✗ 起穿 |
| 0.30 | −0.0466 | −0.0466 | −0.0466 | ✗ |

三个判断：

1. **`mix ≤ 0.22` 时整圈的 Δmin 与静止本底逐位相同** ⇒ 整圈一点没恶化，行程是被 `mix` 卡死的，不是被「转了多少度」卡死的。
2. 绑定点是 **L2 的两只兄弟环中轴圆相切**，`Δmin` 塌到 −0.045 正是 `−2r` 的量级特征。
3. `ρ` 越小上限越松（α 细丝 1/137 时能到 0.45），层数越深越紧 —— **它不是一个结构常数**。

### 22.5 顺带说清「正视图 / 俯视图」

老师提到「这应该是网页正视图的俯视图」：从**俯视**（`pit=90°`）看，L1 环簇沿 L0 的环面滑行，
一圈下来应该绕 L0 走满整圈；从**正视**看，它在 L0 的两侧之间来回。

改完之后两视图对得上：俯视看是**顺/逆时针绕一圈**，正视看是**从一侧经过顶端到另一侧**——
同一个单向圆周运动在两个投影下的样子，不再是「左转四分之一又右转四分之一」。
