# 勾股树 网页版 —— 使用与原理说明

> 原版：`勾股树.nb`（Wolfram 分形树，作者 Ed Pegg Jr. 风格的分形树）
> 网页：`勾股树PythagorasTree.html`（**单文件、双击即用、零外部依赖**）
> 网页复刻两个参数与原版**一一对应**，另外加了一层「配色」开关（原版没有）。

---

## 1. 原版在做什么

`.nb` 里只有两格有效代码。

**第 1 格 —— 生成树（纯几何，与颜色无关）**

```mathematica
PythagorasTree[p1_, bend_ : 12] := Module[{p = 2^p1, xx = 0, yy = 0, scale = -1, f = N[π/bend], ...},
  cc = Cos[f]; ss = Sin[f];
  a1 = -cc ss;  a2 = cc^2;
  b1 = a1 + a2; b2 = -a1 + a2;
  c1 = b2;      c2 = 1 - b1;
  d1 = 1 - a1;  d2 = 1 - a2;
  s[0] = 1;
  tree = {{{xx, yy}, {xx+scale, yy}, {xx+scale, yy+scale}, {xx, yy+scale}, {xx, yy}}};
  While[!done, ...]; Polygon /@ tree]
```

要点：

- **两个子方块的边长就是 `cc` 与 `ss`**，而 `cc² + ss² = 1` = 父方块边长²
  —— 这就是「勾股树」这个名字的来历：**两个子方块面积和 = 父方块面积**。
- `bend = 4` ⇒ `f = π/4` ⇒ `cc = ss = √2/2`，两块一样大 ⇒ **课本上那棵左右对称的标准勾股树**。
  `bend = 2` ⇒ `f = π/2` ⇒ `cc = 0`，退化成**一条直线**。
  `bend = 5.35`（原版默认）⇒ 折角 33.64°，长出来的是一棵**卷曲的螺旋树**。
- 每进一层，`m` 加 1；当 `m == p`（`p = 2^steps`）或边长平方 `< eps = 0.005` 时**回溯**到某个未展开的节点继续。
  用的是显式栈（`s[]` 计数表 + `x2/y2/u2/v2` 暂存表），不是递归。
- `tree` 里每一块是 **7 个顶点的自交折线**：它是「两个子方块的并集」的边界，
  两个子方块只在**公共角点**相碰。Mathematica 的 `Polygon` 按**非零环绕规则**填充，
  所以得到的是并集；描边也只走真实方边，不会画出内部那条假想对角线。
- 第 0 块（树干）是普通的 5 点闭合正方形。

**第 2 格 —— 画出来（含配色）**

```mathematica
Manipulate[
  Graphics[{With[{pt = PythagorasTree[m, n]},
     MapIndexed[{
        EdgeForm[{Thickness[.005], ColorData["Rainbow"][1 - First@#2/Length[pt]]}],
        Opacity[.7],
        ColorData["Rainbow"][First@#2/Length[pt]],
        #} &, pt]]},
   ImageSize -> {400, 400},
   Background -> Append[ColorData["Rainbow"][0.5], .3]],
  {{m, 3, "steps"}, 1, 4, 1, Appearance -> "Labeled"},
  {{n, 5.35, "bend"}, 2, 10},
  SaveDefinitions -> True]
```

| 原版这一行 | 含义 | 网页对应 |
|---|---|---|
| `ColorData["Rainbow"][i/N]` | 第 `i` 块的**填充色**，按块序号在彩虹上取色 | 同（见 §3 配色） |
| `ColorData["Rainbow"][1 - i/N]` | 第 `i` 块的**描边色**，序**反着来** | 同 |
| `Opacity[.7]` | 填充不透明度 0.7 | 「填充不透明度」滑条，默认 0.70 |
| `Thickness[.005]` | 描边粗细（相对图宽的比例） | 「描边粗细」滑条，默认 0.005 |
| `MapIndexed` 的 `First@#2` | **从 1 开始**索引 ⇒ `i/N` 落在 `1/N … 1` | JS 里用 `t = (i+1)/N` 对齐 |
| 绘制顺序 | 先画的被后画的压住（`MapIndexed` 顺序） | 同（第 0 块先画，最后一块在最上层） |
| `Background -> Append[Rainbow[0.5], .3]` | 背景 = 彩虹中点色**叠 30% 透明**，实际是合成在**白页**上 | 同（换算成实色，见下） |
| `ImageSize -> {400, 400}` | 固定 400×400 | 改为**自适应**（容器多大画多大，带 DPR 高清） |

背景换算：`Rainbow[0.5] = (35, 234, 79)`，叠 30% 在白底上 ⇒
`0.3 × (35, 234, 79) + 0.7 × 255 = (189, 249, 202)`，即**淡薄荷绿**。
网页在「背景跟随配色」打开时按同一公式算实色，所以视觉一致。

## 2. 原版 2 个可调控件 → 网页对照

| # | 原版控件 | 范围 | 网页控件 | 说明 |
|---|---|---|---|---|
| 1 | `{{m, 3, "steps"}, 1, 4, 1, …}` | 1 – 4，**整数步长** | **steps** 滑条 + 数字框 | 同步、夹取到 [1,4]、取整 |
| 2 | `{{n, 5.35, "bend"}, 2, 10}` | 2 – 10，**连续** | **bend** 滑条 + 数字框 | 同步、夹取到 [2,10]、保留 2 位小数 |

原版的 `Manipulate` 只给这两个控件，网页**一个不少、语义不变**。
另加三个快捷按钮（原版 5.35 / 45° 对称 4 / steps 拉满 4），只是省得手拖。

**块数随参数怎么变**（实测，与 Python 参考实现逐块相同）：

| steps | bend | 块数 N | 外形 |
|---|---|---|---|
| 1 | 5.35 | 4 | 树干 + 3 块 |
| 2 | 5.35 | 16 | 一小丛 |
| 3 | 5.35 | **210** | 原版默认，卷曲螺旋树 |
| 4 | 5.35 | **670** | 再深一层 |
| 3 | 2.0 | 16 | 退化成竖直线条（`cc = 0`） |
| 3 | 10.0 | 128 | 宽扁树冠 |
| 4 | 4.0 | 512 | 45° 对称标准勾股树 |
| 2 | 7.7 | 16 | 细长 |

## 3. 网页多出来的部分（原版没有，不影响对照）

### 3.1 配色（colormap）

原版写死了 `ColorData["Rainbow"]`，网页把它做成可选项：**共 19 种**。

| 位置 | 名称 | 来源 |
|---|---|---|
| 第 1 位 | **mmaRainbow** | 「Mathematica 风格彩虹」，**默认**，见下 |
| 2 – 19 位 | hsv / turbo / jet / rainbow / viridis / plasma / magma / inferno / cividis / cool / spring / summer / autumn / winter / hot / gray / copper / pink | 与「频率弦投影」页**同一套**已核对的配色基础设施 |

- 其中 `viridis / plasma / magma / inferno / cividis / turbo` 是 **matplotlib 官方 256 级色表**（逐级原样内联）；
  `hsv / jet / rainbow / cool / spring / summer / autumn / winter / hot / gray / copper / pink` 按公开公式现场计算。
- 换配色**只改颜色**，几何一字不差（桩测里有专门一条断言守着）。

> ⚠️ **关于 mmaRainbow 的诚实声明**
> Mathematica 的 `ColorData["Rainbow"]` 数据**内置在内核里**，不随发行版以数据文件形式提供。
> 本机只装了免费的 **Wolfram Player**，它的内核不对外求值（`-run` / `-script` / stdin / `Print` 全部无输出）；
> 在系统文件里翻遍 `ColorData.mx`（只有名字表 + 346 个 X11 命名色）与 `DataPaclets/`，
> 也**拿不到渐变的 RGB 数据**（试过 hex 簇分析、float64/float32 游程扫描，都是 0）。
> 因此 mmaRainbow 是**用 13 个控制点拟合出来的**（控制点见 `_pt_web_dev/ref.py` 的 `RAINBOW_STOPS`）：
> **走向、端点色、中点色与 Mathematica 一致，但不是逐位相同**。
> 需要逐位精确请以 Mathematica 原生输出为准。

### 3.2 其它附加

- **扫描 bend**：让 `bend` 在 2 – 10 之间自动来回扫动，直接看见树形连续变化（原版得手拖滑条）。
  扫描中随时可停，停下后还会回调滑条与数字框。
- **填充 / 描边开关**：单独关掉填充或描边看几何骨架（调试与讲解用）。
- **背景色**：关掉「背景跟随配色」后可任选白 / 黑 / Gray / 深蓝或自取色。
- **保存 PNG**、**复制参数**、**重置为原版默认**。
- **实时读数**：块数 N、steps、折角 `f = π/bend`（同时给角度与弧度）、bend、包围盒、当前配色。

## 4. 验证（都做了，不是「看着像」）

### 4.1 几何对拍：与 Python 参考实现逐点相同

`_pt_web_dev/ref.py` 把 `.nb` 的 `PythagorasTree` **逐字复刻**成 Python（显式栈 + 计数表 + 暂存表，
连 `eps = .005`、`scale = -1`、`xx = yy = 0` 的坐标变换都照搬）。
`dump_expect.py` 导出 `expect_tree.json`，`pt_stub_test.js` 拿它逐项对拍。

8 组用例覆盖：

- 块数 `N` 完全一致（4 / 16 / 210 / 670 / 16 / 128 / 512 / 16）
- 首块、末块、**抽样块**（第 0/1/2/70/105 块…）的 7 个顶点逐点比对，偏差 `< 1e-12`
- **14 列顶点总和**一致 —— 一次覆盖全部顶点的两条坐标，等价于逐块比对
- 包围盒一致，偏差 `< 1e-12`

另有结构性断言，把「勾股」这件事本身钉死：

- 第 0 块 5 点（树干正方形），其余每块 7 点（两子方块并集边界）
- 每块首尾顶点重合（闭合折线）
- 第 1 块里子方块 A 的两条边都 `= cc = 0.832488`、相邻两边垂直
- 第 1 块里子方块 B 的两条边都 `= ss = 0.554044`、相邻两边垂直
- `cc² + ss² = 1`（= 父边²）—— 面积守恒

### 4.2 配色逐点核对

- `Rainbow(0) = #780085`、`Rainbow(0.5) = #23ea4f`、`Rainbow(1) = #b40426`（与参考实现一致）
- 11 个采样点上三条通道逐点一致
- 换配色后**几何 JSON 一字不差**；`stroke` / `fill` / `closePath` 次数 = 块数

> 一个细节：Python 的 `round()` 是「四舍六入五取偶」，JS 的 `Math.round` 是「五入」，
> 在 `228.5` 这类半整数上会差 1。所以桩测里**先按 Python 同款语义量化再比**，
> 比的是「同一套连续值 + 同一套量化规则」，与逐位比对等价，且不受量化规则差异干扰。
>
> 顺带查出并修掉一个**真 bug**：生成器最初把控制点 `×255` 后**取了整**
> （`121.89 → 122`），导致插值出来的中间色与参考实现差开（实测 `t=0.625` 处 JS `161.5` / Python `161`）。
> 现在控制点保留**归一化浮点**，JS 侧插值式与 Python **同序**，最后才 `×255`。

## 6. 已知差异（都无害）

| # | 差异 | 说明 |
|---|---|---|
| 1 | `ImageSize -> {400,400}` 固定尺寸 → 网页自适应 | 提升清晰度用；比例与构图算法不变 |
| 2 | mmaRainbow 是**控制点拟合**，非官方逐位数据 | 见 §3.1 的诚实声明 |
| 3 | 原版靠拖滑条看变化 → 网页多一个「扫描 bend」 | 附加功能，不影响手动参数 |
| 4 | 原版 `Rainbow[0.5]` 叠 30% 透明 → 网页算成实色 | 白色页面上视觉等价；换配色时会跟着变 |
| 5 | 原版无「填充/描边开关」 | 附加功能，默认都开着，与原版一致 |
| 6 | JS 与 Python 的 `round` 半整数规则不同 | 只影响末位取整（±1/255），不影响可测一致性；桩测已按 Python 语义对齐 |
