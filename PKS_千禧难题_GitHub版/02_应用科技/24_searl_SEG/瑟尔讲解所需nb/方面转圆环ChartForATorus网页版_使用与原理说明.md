## 零、这个演示在做什么

一个参数 **λ** 把「环面（甜甜圈）」连续地剪开、摊平：

| λ | 形态（nb 的 `PlotLabel`） | 几何 |
|---|---|---|
| `0` | **2-Torus** | 椭圆截面环面，主半径 2π/3、管半径 π/3、轴向 1，中心 (π, π, 0) |
| `0.5` | **2-Torus** | 管子被抻长、管壁变薄 |
| `1` | **Cylinder** | 圆柱面，半径 π、轴 (π, π)、z = π − v |
| `1.5` | **Plane** | 圆柱被剪开、开始铺平 |
| `2` | **Plane** | xy 平面上的 2π×2π 正方形，z ≡ 0 |

右边两个转盘（θ 红针 / φ 蓝针）在 (u, v) 参数域里挑一个点，绿色小球就落在它被映射到的位置上 —— 拖 λ，就能看着这个点从环面「走」到平面。

makeHand[fl_, bl_, fw_, bw_] :=
    Polygon[{{-bl,-bw},{-bl,bw},{fl,fw},{fl + 8 fw,0},{fl,-fw}}/10];

## 二、五个必须先讲清的技术点

### 2.1 两支在 λ = 1 处**严丝合缝**，不是硬切

这是这个 nb 最漂亮的地方。把 λ = 1 代入左支：

```
c = -2 - 1 + (1-1) cos v = -3
x = (π/3)(3 - cos u·(-3)) = π(1 + cos u)
y = (π/3)(3 - (-3) sin u) = π(1 + sin u)
z = -1·(v - π) + 0 = π - v
```

再把 λ = 1 代入右支：

```
x = 0·v + (2-1)(π + π cos u) = π(1 + cos u)      ✓
y = 0 + (2-1)(π + π sin u)   = π(1 + sin u)      ✓
z = (1-2)(v - π)             = π - v             ✓
```

**逐项相等**。所以 λ 从 0 推到 2 的整段形变是**无缝**的，画面上不会跳。（`ref_test.py` 里对 5 组 (u,v) 做了 `λ = 1 ∓ 1e-12` 的左右极限对拍。）

### 2.2 三个整数 λ 的闭式

| λ | x | y | z |
|---|---|---|---|
| `0` | `π + (2π/3 + π/3·cos v)·cos u` | `π + (2π/3 + π/3·cos v)·sin u` | `sin v` |
| `1` | `π(1 + cos u)` | `π(1 + sin u)` | `π − v` |
| `2` | `v` | `2π − u` | `0` |

λ = 0 的那个是**椭圆截面环面**（径向起伏 π/3、轴向起伏 1，不是圆管）—— 这点容易看错，`ref_test.py` 用 179×179 采样与解析式逐点对拍过。

### 2.3 `SphericalRegion -> True` 的含义，直接决定相机怎么写

它让「旋转视角时画面大小不变」。网页版的等价做法是：**相机始终挂在 `PlotRange` 的包围球上**，而不是挂在图形本身上。

```
PlotRange = {{-0.2, 2π+0.2}, {-0.2, 2π+0.2}, {-π-0.2, π+0.2}}
包围球半径 R = √((2π+0.4)² + (2π+0.4)² + (2π+0.4)²)/2 = 5.788
眼位 = 中心 (π, π, 0) + unit(ViewPoint) × 倍率 × R
```

nb 没写 `ViewPoint`，用的是 Mathematica 默认方向 `{1.3, -2.4, 2}`。所以「nb 默认视角」按钮就是把这个方向换算成 yaw / pitch：

```
yaw   = atan2(-2.4, 1.3)              = -61.57°
pitch = atan2(2, √(1.3²+2.4²))        = +36.17°
```

默认距离倍率取 2.2（黄金值里用 2.6 做投影对拍，两者只差一个缩放，基向量与焦距完全一致）。

### 2.4 `b` 边界红线的条数会随 λ 变 —— 这不是 bug

- **λ = 0 时**：`v = 0` 与 `v = 2π` 的 `cos v / sin v` 相同 ⇒ 两条曲线**重合**。所以画面上只看到 **2 条**独立红线（一条赤道大圆 + 一条管截面环）。
- **λ = 1 时**：`z = π − v` 让 v 变成线性 ⇒ `v = 0` 落在 z = π（上圆）、`v = 2π` 落在 z = −π（下圆），加上 `u = 0 / u = 2π` 重合成的**一条竖直线**。画面上是 **3 条**。
- **λ = 2 时**：四条边各自独立 ⇒ 正方形的 **4 条边**。

`ref_test.py` / 桩测里都留了这条断言。

### 2.5 半透明曲面为什么不能直接逐面画

原版是 `Opacity[0.8]`。网页版如果照字面「每个四边形各画一次 0.8 透明填充」，相邻四边形的抗锯齿边会各覆盖约一半 ⇒ 边界像素的合成 alpha 明显低于内部，**整个曲面上会浮出一层网格状的条纹**（第一版实拍就是这样）。

做法改成**两层**：

```
① 离屏画布上按 alpha = 1 画完所有四边形（这样接缝被完全盖住）
② 把离屏画布整体以 globalAlpha = 0.8 贴回主画布
③ 边界线 / 网格线 / 标架 / 绿球再画在第二层
```

代价是「透过前面看到后面」的层次感弱了一点（对 0.8 这种高不透明度，视觉差异很小），换来的是干净的曲面。

## 三、自写的 3D 内核 `_shared/mini3d.js`

三个 nb（本页 + `DiagonalsOfPolyhedra` + `RecursiveExercisesVITori`）都是 3D 场景，所以写了一个共用内核，**纯 Canvas2D、零依赖**（不引 three.js，保持单文件）。

```
世界坐标 → lookAt 正交基(s,u,f) → 透视/正交投影 → 深度排序(painter) → 绘制
```

| 部分 | 做法 |
|---|---|
| 相机 | `cam(W,H,fovY,eye,target,up)`，`focal = (H/2)/tan(fovY/2)`，fovY = 32° |
| 投影 | `proj(cam, p) → [sx, sy, zv]`；`zv < 1e-6` 返回 NaN 由调用方跳过 |
| 深度排序 | 每个图元取「代表深度 zv」= 各顶点的 zv 均值，减去 `depth` 偏置；**远的先画** |
| 光照 | 把法向变换到**相机空间**（光固定随相机，这是 Mathematica 的做法）再算 Lambert；法向翻到朝相机一侧（双面），所以任何角度都有明暗层次 |
| 球体 | 屏幕空间圆 + `createRadialGradient` 三点渐变，半径 = `r · focal / zv` |
| 接缝 | `alpha >= 0.999` 的四边形自动补一圈同色描边，盖掉抗锯齿细缝 |

图元统一进一个列表（`quad / line / polyline / sphere / text`），一次排序一次绘制 —— 这样「红线压在半透明曲面上」也能通过 `depth` 偏置精确控制。

内核有**独立自检** `_shared/selftest_mini3d.js`（**37 项全过**），其中 40 个世界点的屏幕坐标与 Python `project()` 逐值对拍（误差 ≤ 1e-5，深度 ≤ 1e-8）。

### 2026-10-07 这轮修掉的坑（都留了断言）

1. **`bindPair` 把 DOM 元素当函数调用** —— 反向刷新 UI 的 `push` 函数被元素覆盖，`syncAll()` 一进 `boot()` 就抛 `TypeError`，**主循环根本没起来**（表现为读数全是空的）。已把 `REF[sid]` 改成存 `push` 本身。
2. **`buildMesh` 快速路径的系数抄错** —— λ ≤ 1 支的 `z` 项写成 `(2−λ) sin v`，正确是 `(1−λ) sin v`，导致 **z 方向整体错一倍**（λ=0 时 bbox 变成 ±2 而不是 ±1）。A 区逐点对拍抓出来的；已改成 `1 − λ`，并把「快速路径 ⇔ 逐点公式」单独立了一条桩测断言。
3. **`gifFramesOf` 在 canvas 元素上调 `getImageData`** —— canvas 元素没有这个方法，必须走 `getContext('2d')`。真实页面点「导出 GIF」会直接报错。
4. **`gifFramesOf` 传 `ImageData` 而不是 `.data`** —— 编码器按下标读像素会拿到 `undefined`，**整帧被量化成同一个颜色**，导出的 GIF 只有 **0.04 MB**（正确是 1.23 MB）。已加回归断言：`gifFramesOf` 每帧必须是长度 `W*H*4` 的像素数组。
5. **`boundaryLoops` 忽略传入的采样数** —— 写死 48，导致与 Python 参考的 68 点对不上（196 vs 68）。已改为按传入 n 采样，渲染侧另传固定 160 保证红线平滑。
6. **`bReset` 重新赋值 `S`** —— `window.__CT__.S` 会失效（指向旧对象）。改成 `Object.keys(d).forEach(k => S[k] = d[k])` 就地覆盖，并留了断言。
7. **光照方向 z 分量写反** —— 相机空间里 `z` 指向远方，光源 z 必须为负（朝相机一侧），否则正对相机的面全黑。已改成 `(0.42, 0.55, −0.72)` 这一组。
