## 零、统一模型：一张图看完全部的绑定关系

老师的要求是「**右边浮窗的参数一调，左边的每一张图都会变化**」。做法是把三套原本各自独立的参数
收敛成**唯一的真值来源** —— `S.uni`：

```
S.uni = { n, r, ρ, sign, lock2, lock3 }

  n    定子 / 滚筒半径比   ★ 必须是 ≥1 的整数（滑条 1~24，step 1）
  r    滚筒半径            0.05 ~ 3
  ρ    笔距比              0 ~ 1        （方向由 sign ∈ {+1,−1} 单独管，不再塞进 ρ 的符号里）
```

由这三件套**派生**出四张图的全部参数，改任何一处就 `syncFromUniAll()` 一次，四张图同时重绘：

| 去向 | 派生式 | 说明 |
|---|---|---|
| ① 单滚筒 | `R = n·r`、`k = sign·ρ`、`ratio = true`、`p = 1`、`q = n` | **R/r 恒为整数比 n**，有理比锁定永远成立 |
| ② 本轮分解 | `A = R + r`、`ω_A = 1`、`B = ρ·r`、`ω_B = (R+r)/r = n+1` | 锁定态直接吃统一核 |
| ③ 等价构造 | `n`、`r` 同名同源 | 卡片标题就写着「＝①的 n」「＝①的 r」 |
| ④ 多滚筒 | 定子圈半径 `R`、转子个数 `n`、转子半径 `r` | 见下节 |

**② ③ 的「锁定」开关**：② 卡片有 `🔒 跟随统一模型`，③ 也有（`lock3`）。取消勾选可以单独手改，
但一改 ① 的 n/r/ρ，它们又会被拉回来（这正是"同步变化"的要求）。
③ 的 `n` / `r` 滑条**直接绑在 `S.uni` 上**，不是绑在 `S.v3` —— 所以拖 ③ 的 n 等于拖 ① 的 n。

### ★ 关键的整数比保证

`n` 的滑条 `step=1`、数字框 `step=1`、`syncUni()` 里还有一次 `Math.round()` 兜底：

```js
u.n = Math.max(1, Math.min(24, Math.round(u.n) || 1));   // 任何人都塞不进小数
const R = Core.uniR(u);                                  // R = n · r，恒成立
```

于是 `R/r = n` 永远是整数 ⇒ `ω_B/ω_A = n+1` 也是整数 ⇒ **周期恰为 2π，一整圈必然闭合**
（桩测里用 `Core.periodMax(1, n+1) === 2π` 和 `epi(…,0) === epi(…,2π)` 两条数值断言守住）。

## 二、去重：三份 nb 的曲线是同一条公式

逐字抄下三份 nb 的轨迹表达式后可以发现，**它们都是「两个旋转向量之和」**（本轮 / epicycle 模型）：

```
P(t) = A·cis(ω_A·t + φ_A) + B·cis(ω_B·t + φ_B)        cis x = (cos x, sin x)
```

| 来源 | A | ω_A | φ_A | B | ω_B | φ_B | 原版写法 |
|---|---|---|---|---|---|---|---|
| A · Epitrochoids | `1 + p/q` | 1 | 0 | `α·p/q` | `(1+p/q)·q/p` | 0 | `(r1+r2)cis[ω1] + r3 cis[ω2]` |
| B 单元1 | `R + r` | 1 | 0 | `−a·r` | `(R+r)/r` | 0 | `(R+r)Cos θ − a r Cos[(R+r)θ/r]` |
| B 单元2 | 1 | 1 | 0 | `1/4` | 4 | 0 | `RotationTransform[a][{1,0}] + RotationTransform[4a][{1/4,0}]` |
| B 单元3 | `1 + r` | 1 | 0 | `a` | `1 + r` | 0 | `(1+r)Cos θ + a Cos[(1+r)θ]` |
| B 单元4/5 | `(n+1)·r` | 1 | 0 | `−r` | `n + 1` | 0 | `ReIm[(n+1)r E^(It) − r E^(I(n+1)t)]` |
| C · 第 i 轮 | `开关` | 1 | `iπ/2` | `开关·r_i` | `s_i·d_i` | 0 | `A(cos(t+φ_i) + r_i cos(s_i d_i t))` |

**这一条公式就是"去重"的落点**——A 的 Spirograph、B 的四种探索、C 的四个轮子，全都是它的特例。验证脚本 `ref.py` 对每条 nb 原始公式逐点比对，**98 项全部误差 0（≤2e-15）**。

顺带得到两个原本散落的事实（现在写进了页面读数）：
- **滚动判据**：只要 `ω_B/ω_A > 1`，取 `r = A·ω_A/ω_B`、`R = A − r > 0`、`ρ = B·ω_B/(A·ω_A)`，它就能读成"定子 R + 圆外滚圆 r"的外摆线；否则（`ω_B ≤ ω_A`）只能当自由双圆本轮。视窗②会实时给出这个判读。
- 于是 **B-单元2 `(1, 1/4, ω=4)` 其实是外摆线**（R=0.75, r=0.25, ρ=1），而 B-单元5 的 n=12 正是 R=12、r=1 的外摆线 —— 与 C 的"大轮长周期 + 小轮短周期"是同一回事。

### ① 单滚筒 · 几何构造（A ＋ B单元1/3）

- **画什么**：定子（半径 R）→ 滚筒（半径 r，圆心 `(R+r)cis θ`）→ 臂 → 笔尖；轨迹 t∈[0, θ]；可叠网格。
- **两套原版外观**（右侧「配色方案」一键切换，同时切换图层默认值）：
  - **nb#1 半透明盘**：定子 = `Green` 填充 `Opacity[0.1]`；滚筒 = `Blue` 填充 `0.2`；笔距盘 = `Blue` 填充 `0.1`（半径 `|ρ|·r`）；臂 = `Blue` 线 `0.2`
  - **nb#2 描边圆**：定子 = `Blue` 粗圆；滚筒 = 黑粗圆；臂 = 黑线；轨迹 = `Red` 粗；笔尖 = 红大点；网格 = `GrayLevel[0.9]`，步长 0.5

- **视窗半宽**：`pr = R + r·(1 + Max[1, |ρ|])` —— R=1 时与原版 nb#1 的 `PlotRange` **逐字相同**。
- **θ 上限三档**：`1 圈 = 2π（就是完整闭合）` / `2 圈 = 4π（原版 2(p+1)π）` / `3 圈 = 6π`。
  因为 R/r 现在恒为整数，**「1 圈」这一档就已经是闭合的**（原来的「完整闭合 = 2π·p」被这一档吸收）。

### ② 本轮分解 · 两向量之和（去重出的统一内核）

- **画什么**：蓝色向量 `A·cis(ω_A t+φ_A)` + 红色向量 `B·cis(ω_B t+φ_B)`（从蓝向量末端起画）→ 合成笔尖；两个虚线圆是本轮所在圆；深蓝曲线是 t∈[0, t上限] 的合成轨迹。
- **控件**：A、ω_A、φ_A、B、ω_B、φ_B、t 上限；4 个预设（B单元2 双圆 / B单元3 / 滚动外摆线 R=6 r=0.5 / C 的轮1）；`↔ 由①同步`（把视窗①的统一核六元组搬过来）、`取整周期`（按 `2π·分母(ω_B/ω_A)` 取一整周）。
- 这张图把散在三份 nb 里、看不见的"本轮结构"显式画出来了：**①和④的所有曲线都能在这里找到对应的两个圆**。
- 实时判读：`滚动等价成立 ⇒ R=…, r=…, ρ=…` 或 `非滚动（r = A·ω_A/ω_B 使 R ≤ 0）`。

### ③ 等价构造 · 双生成与线族包络（B 单元4/5）

三块画面共享 `n, r, u`：

- **面板A · 真滚动圆**：定子圆 `n·r`（`Blue` 粗）+ 半径 `r` 的滚动圆（圆心 `(n+1)r·cis u`）+ 臂 + 红笔尖；曲线 `ParametricPlot[双生成式, {t, 0, u}]`（可切"只画到 u"）
- **面板B · 双生成大圆**：同一个定子圆 + **半径 `(n+1)r` 的大圆**（圆心 `−r·cis((n+1)u)`）+ 臂 + 红笔尖 —— 笔尖在这两种画法下**轨迹完全相同**，这就是外摆线的"双生成定理"
- **面板C · 线族包络**：曲线 + `m` 条 `InfiniteLine`（半透明黑，原版是 `Opacity[1/5]`）+ 动圆 `(n+2)r`（半径 `2r`）+ 红色动弦 —— 曲线是这族动弦的**包络（切线集合）**
- **控件**：`n`(1~24，**＝①的 n**)、`r`(0.05~3，**＝①的 r**)、`u 滚动角`、`m 线族条数`(3~201)、`步进段数`、6 个图层开关。原版 B单元4 写死 `n=3,r=1`、单元5 写死 `n=12,r=1`，这里放成滑条，默认跟随统一模型。
- **两条已数值证明的几何不变量**（页面读数 + 桩测都验）：
  - `|笔尖 − A圆心| = r`、`|笔尖 − B圆心| = (n+1)r`、`|B圆心| = r`
  - **线族每一条都真的与曲线相切**（曲线点到该直线的最近距离，最大 2.3e-15）

### ④ 多滚筒 · 定子 ＋ n 个外围转子（C，**2026-10-07 重做**）

原来是「大轮(半径 1) + 四个小轮」的固定四轮图。现在改成 **① 那套系统的 n 个副本**：

- **画面1 俯视轨迹**
  - **定子 = 红圈**，半径 `R = n·r`（与 ① ② ③ 的 R 是**同一个数**）
  - **n 个转子**，半径 `r`（与 ①②③ 的 r 同一个数），圆心均匀落在半径 `R+r` 的圆上、彼此错开 `2π/n`
  - 每轮一个十字线（绕轮心旋转 `k_i·θ`）+ 一个笔尖 + 一条轨迹
  - 辐条：中心 → 各转子圆心
- **画面2 高度波形**：n 条 `y(θ)` 曲线，纵轴自适应到 `±reach`，横轴 π 刻度
- **参数表**：`转子 | 开 | 半径 | 方向 | 角速 s | 笔尖 (x, y)`
  - **半径列是只读的**（就写 `r`），因为半径已经由统一模型定死了
  - 角速列默认 `s_i = n+1`（标准外摆线），**改 n 时自动跟着 `n+1` 走**；但如果你手改过某几个轮的角速，再改 n 就不再覆盖你的设置（`S.v4.stdK` 记住上一轮的标准值来判断）
- **公式**（页面底部方程条实时显示）：
  ```
  P_i(t) = (R+r)·cis(t + φ_i) + ρ·r·cis(k_i(t + φ_i))     φ_i = 2πi/n，k_i = s_i·d_i
  ```
  ⇒ **第 0 个转子（φ=0）与 ① 的曲线完全重合**，第 i 个只是时间平移 φ_i。
- **⚠ 一个要提醒的数学事实**：当 `k_i = n+1`（全部「标准外摆线」）时，外摆线本身有 n 重对称，
  所以 **n 条轨迹会完全重合**（看起来只有一条曲线）—— 这不是 bug，正是「④ = ① 的 n 个副本」的字面意思。
  页面读数里会显式写出这句话；想看成各自独立的曲线，点预设 **「原版四轮」**（`s_i = 1`）。
- **预设**：`原版四轮`(全开/正向/角速=1) / `全部标准外摆线`(s_i = n+1) / `交替反向` / `慢速`
- 颜色：前 4 个沿用 `Darker[{Blue,Green,Red,Yellow}]`（=`RGBColor[(0,0,2/3),(0,2/3,0),(2/3,0,0),(2/3,2/3,0)]`，
  从 nb 缓存里读出来的 `Darker[Blue] = RGBColor[0,0,Rational[2,3]]`）；第 5 个起按**黄金角 0.618** 跳色相，
  保证相邻转子颜色差异最大（一开始用 `i/30` 递进，n=6 时后两个轮浅得几乎看不见，已改）。

### 高清是怎么来的

导出期间把全局的 `PIX`（超采样倍率）临时抬高：

```js
const dpr = (window.devicePixelRatio || 1) * PIX;   // ctxOf 里
```

于是画布的 backing store 变成 `CSS尺寸 × PIX`，**线条和文字是真·高分辨率重绘，不是把小图放大插值**。
`PIX = 900 / 画布CSS长边`（夹在 1~4 之间，且总像素不超过 1.6 M），所以成品稳定是 **900×900**。

### 纯手写 GIF89a 编码器（不引任何外部库）

| 环节 | 做法 |
|---|---|
| 抓帧 | `S.tau = i/n → applyTau() → render()`，把画布合成到**白底**离屏画布再 `getImageData`（画布本身是 `clearRect` 出来的透明底，不合成白底会整片黑） |
| 量化 | 全部帧一起做 **6 bit/通道直方图**（262144 桶，同时用 `Float64Array` 累加 8 bit 真值）→ **中位切分（median cut）**切到 ≤256 色 → 全局调色板 |
| 映射 | 6 bit 键 → 调色板下标的**惰性缓存**（`Int16Array(262144)`，人眼加权平方距离） |
| 编码 | **LZW 变长码**（ClearCode / EOI / 码长 9→12）+ 255 字节子块；时序按 gif.js 的口径：**先打包、后升码长** |
| 体积 | 单张超 5 MiB 就**自适应收敛**：30 帧 → 21 → 16 → 缩画幅 80% → 62%，最多 5 档 |

**抓帧只重画目标那一块**：`render()` 认全局 `ONLY / ONLYP`（`'v1'/'v2'/'v3'/'v4'`，
③ 再细分 `'A'/'B'/'C'`），否则 30 帧 × 7 块 = 210 次全量重绘，白白慢 4 倍。

## 六、与原版的差异（诚实清单）

1. **视窗半宽自适应**。原版 nb#2 单元1 对 `R=6, r=0.5` 写死 `PlotRange->{-12,12}`；本页统一用 `pr = R + r(1+Max[1,|ρ|])`，正好等于曲线最大半径（R=1 时与 nb#1 原式完全一致），不再有固定留白。
2. **网格范围**。原版 `gridlines = Table[{x, GrayLevel[0.9]}, {x,-6,6,0.5}]` 只覆盖 ±6（而视图是 ±12）；本页网格铺满当前视图，步长可调（默认 0.5）。
3. **线族按 `InfiniteLine` 画**（延伸到框外）。红色动弦仍是 `Line`（有限长 `4r`）—— 这正是原版单元4 里两种线型的区别，照抄。
4. **关闭的轮子在俯视图里不画轨迹**。原版四个 `ParametricPlot` 都画，开关关掉的轮子 `y_i ≡ 0` 会在原点留下一个退化点；本页省掉该点，但**波形里仍保留 y=0 的水平线**（与原版一致）。
5. **③ 的 `n`、`r` 可调**。原版在 `With[{n=…, r=…}]` 里写死（单元4 为 3/1，单元5 为 12/1）。本页把它**直接绑到统一模型**（改 ③ 等于改 ①）。
6. **④ 与 nb#3 原版的关系**：原版是"半径 1 的大轮 + 四个半径/速度各自独立的小轮"（各轮半径上限 √½）。
   本页把大轮换成**统一模型的定子 R**、四轮换成 **n 个半径统一为 r 的转子**（半径不再独立，因为它现在由统一模型定死），
   但仍保留每轮的 **开关 / 方向 / 角速** 三个自由度，并提供「原版四轮」预设（全开 + 正向 + 角速 1）还原原版那种各转各的观感。
   这是本轮改造里**唯一一处有意偏离原版语义**的地方，为的是满足"半径与个数都要和前三张图联动"。
6. **坐标轴/边框**：原版 `Axes->True`（① ② ④波形）与 `Frame->True`（③）照原样保留，另给一个总开关。刻度样式是近似复刻（Mathematica 的刻度密度算法未公开）。
7. 本页是**三份 nb 合并后的工作台**，不是任何一份原版的逐像素复刻；视觉上追求"每个图层/颜色/开关都对得上号"，像素级一致不作为目标。

### 2026-10-07 这轮修掉的坑（都留了断言）

- **`syncFromUniAll()` 里的键名大小写**：写的是 `['cUn','cur','curho','cth','cN','cR3']`，
  而 `REF` 里的键实际是小写的 `cn` / `cr3`（由 `bindSlider('sN','vN',…)` 生成）。
  `if (REF[k])` 取到 `undefined` 直接跳过 ⇒ **拖 ③ 的 n 滑条，④ 不跟着变**（老师实测发现的就是这个）。
  修掉之后，① 的滑条/数字框、③ 的滑条/数字框、② 的锁定，四条路径全部实测联通了。
- **`ensureWheels()` 不跟 `n+1`**：n 从 4 改到 6 时，转子角速还停在旧的 5（应该是 7），
  ④ 就不再是「① 的 n 个副本」了。加了 `S.v4.stdK` 记住上一轮的标准值 ——
  **全部还是标准值 ⇒ 整体跟到新的 n+1；手改过 ⇒ 不覆盖老师的设置**。
- **DOM 桩每次返回新元素**：`_stubQueryAll('[data-w]')` 原先每次 `mkEl` 造新桩，
  于是 app 绑在一批上、测试 fire 另一批，事件全丢。加 `_cache` / `_cacheN` 按 n 缓存；
  另外 `ws{i}/wo{i}/wd{i}` 必须**同时进 `REG`**，因为 `buildWheelUI` 的快路径是用 `getElementById` 回刷的。
- **④ 第 5 个转子起颜色太浅**：原来 `hsv2rgb(i/30+0.08, 0.62, 0.72)`，n=6 时后两个轮在白底上几乎看不见。
  改成黄金角 `hsv2rgb(0.62 + (i-4)·0.618034, 0.80, 0.62)`。
- **一次性回传 ~30 MB base64 把 CDP 卡死**：`Runtime.evaluate{returnByValue:true}` 碰到巨大结果会长时间不返回
  （页面其实是空闲的，探测响应只要 4 ms）。改成 **逐块回传**。
- **Node WebSocket 单条消息上限**：逐块之后 ③面板C 的 GIF 有 4.23 MB ⇒ base64 5.9 MB，
  报 `Max decompressed message size exceeded`。最终方案：页面把结果暂存 `window.__gifOut`，
  Node 用 `gifChunk(off, 400000)` **分片拉**再拼回（桩测里有一条"分片拼回与完整 base64 逐字符一致"的断言守着）。

### 更早修掉的坑

- **统一核的判据**：一开始写成"`ω_B = A/r` 才等价"，其实 `r = A·ω_A/ω_B` 总能解出来；真正的约束是 **`R = A − r > 0`**，即 `ω_B > ω_A`。改对之后才正确区分「外摆线」与「自由双圆本轮」。
- **B 单元3 的笔幅不乘 r**：`(1+r)cisθ + a cis((1+r)θ)` 里第二项振幅是 `a` 而不是 `a·r`，与单元1 的 `a·r` 不同。若当成滚动式会算出 20 点全错，正是这个差异暴露了"两向量之和"才是真正的统一形式。
- **事件委托的闭包**：图层按钮用容器委托，闭包捕获了 `S.v1.layers` 对象；一键切配色时若**替换**该对象，委托就会去改一个废弃对象（点按钮没反应）。改成原地改字段 + 委托内用 getter 取值。
  —— 同样的坑在「恢复默认」上又踩了一次：`S.v1 = {...}` 整体替换会让滑条写进废弃对象，必须**原地改字段**。
- **④ 轮表每次渲染重建会掉监听器**：`refreshReadouts` 里原本重写 `tbody.innerHTML`，会把四轮输入框的事件一起销毁。改为结构只建一次、渲染只更新笔尖坐标列。
- **`step()` 的 `if(!tick0)`**：`tick0` 初值 0 时永远为假，导致首帧后 dt 恒为 0、τ 不动。改用 `null` 判空。
- **③ 面板C 的线族**：原版是 `InfiniteLine`，一开始按有限线段画，包络看起来是"放射状射线"而不是"切线族"。改成延伸到框外后才是正确的 caustic 形状。
