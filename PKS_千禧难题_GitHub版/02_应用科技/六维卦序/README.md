# 六维卦序 · 三源合观

把「六十四卦的六维骨架」和「佛陀罗尼的四六」「规矩数的构造刀数」放在同一张桌上对账。
结论不是「三者是一回事」，而是 **共用同一组数 ≠ 共用同一套结构**。

## 跑法

```bash
node hexagram.cjs      # 全部数值，终端打印
node test-hex.cjs      # 170 项核验（A–P 十六段 + 8 变异 + 5 源清单）→ PASS 170/170
node make-atlas.cjs    # 生成 AAA_四六通达_三源合观.html
node make-lianxin.cjs  # 生成 AAA_良心与异化_六维价值梯度.html
node make-docaudit.cjs # 生成 AAA_算法文档_合观校核.html（读 hexagram.cjs 的 docAudit()）
node _split_frames.cjs _img/raw/X.jpg 前缀 列 行   # 切视频截图拼图（亮度探留白）
node _panels.cjs       # 探 22 张图集各是几行几列面板（行内亮度标准差找黑缝）
node _match4.cjs       # 按探出的面板逐块比对，判定 16 帧与图集的重叠关系
```

零依赖，Node ≥ 14。除 `test-hex.cjs` / `make-*.cjs` / `_panels.cjs` / `_match4.cjs` 外不调用 Node API
（后四个借 `../construct-cost/cdp.cjs` 驱动无头 Chrome，不装 puppeteer）。

## 位序约定（唯一来源，全库不得二义）

```
b = 32·初 + 16·二 + 8·三 + 4·四 + 2·五 + 1·上     即 bit5 = 初爻，bit0 = 上爻
```

泰 = 111000 = 56，否 = 000111 = 7，56 + 7 = 63（严格互为反码）。

🔴 那份《易经 × AI》整理里写的是「bit5 = 上爻」，但它自己给的泰 = 56 只能由「bit5 = 初爻」得到 ——
**是它的文字写反了，不是数字错**。

### C₆₄ = {±1,±3}³ 与六十四卦

三才各占一轴，每轴 4 个位置即四象：

```
x（地）= 2·(2·二 + 初) − 3
y（人）= 2·(2·四 + 三) − 3
z（天）= 2·(2·上 + 五) − 3
```

64 卦 → 64 个互不相同的整数点，往返恒等。乾 = (3,3,3)、坤 = (−3,−3,−3) 是体对角两端，
距离 6√3，恰为全部 64 点中的最大距离。

## 划清的三条线

**① 同基数 ≠ 同构。** (ℤ/2)⁶ 每个非零元阶都是 2；(ℤ/4)³ 有 4 阶元。双射成立，群同构不成立。
「4 与 6 互为对偶」这个说法递进过头了 —— 它是**坐标读法的切换**。

**② 共数 ≠ 共构。** 4×6 = 24 = 4! = 立方体旋转群阶，三个体系都算出 24，
但「四层×六通道」「四象×六爻」「三个元素选一个的排列数」机制上毫无关系。

**③ 数列为真 ≠ 归属为真。** 「物质侧 1,2,4,8,7,5」确实是 2 的幂模 9（周期 6），
也就是 1/7 的循环节 142857 的循环排列。数列是真的；「这代表物质侧」不可验证。

## 从无极到十二地支（页面 §7）

一条链，**两套规则**：

| 次第 | 名 | 数 | 生成式 | 口径 |
|---|---|---|---|---|
| 0 | 无极 | — | — | 立论（周敦颐《太极图说》，原文没有这个数） |
| 1–7 | 太极·两仪·四象·八卦·十六·三十二·六十四 | 1·2·4·8·16·32·64 | 2⁰…2⁶ | 生成（×2，强制） |
| 8 | 十二辟卦 | 12 | **7 + 7 − 2** | **选择**（从 64 里挑） |
| 9 | 十二地支 · 十二月 · 十二辰 | 12 | 挂在第 8 步 | 选择 + 历法挂靠 |

三条硬判据（全部现算，不抄表）：

1. 十二辟卦的挑法：位串（初→上）是「全阳后全阴」或「全阴后全阳」= 阳/阴连号且贴一端。
   两族各 **7** 个，交集恰为乾、坤，**7 + 7 − 2 = 12**。
2. 这 12 个在 Q₆ 上首尾相接成 **12 步闭环**，每步汉明距恰为 1。
3. `64 mod 12 = 4 ≠ 0` ⇒ 12 不是 64 的因子；`12 = 3 × 4` 中 3 不是 2 的幂 ⇒ **2ⁿ 永远到不了 12**。

🔴 **64 与 12 不同轴**：分靠 ×2（生成），周靠挑（选择）。说「64 生出 12」是错的，
说「从 64 里挑 12 个来接历法」才对。历法锚点是复=子=冬至、姤=午=夏至（实测，不是推导）。

## 良心与异化（子页，2026-11-01 建）

源作者第一期 V1《AI 的良心——当六维超立方体遇见〈易经〉》的 16 帧截图，逐帧读了之后做的复算：

| 项 | 结论 |
|---|---|
| 六爻位平均吉凶分 | 初 +0.04 / 二 +0.38 / 三 **−0.63** / 四 +0.26 / 五 +0.57 / 上 −0.29（三爻那根柱子被标签压住，放大 3 倍才读清，**不是 −0.29**） |
| 与《系辞下》对账 | 「二多誉四多惧、三多凶五多功」三条**全中**（二>四、三<0、五最大） |
| 势的极值 | 最高 **兑** 1.25、最低 **艮** −0.92 |
| 🔴 反例 | 位平均势下 **谦排 61/64**（V=−0.63），而视频说「谦六爻皆吉、定为最高原则」⇒ 吉凶 ＝ **位效应 + 卦效应**，位平均只给了前半截 |
| 384 的账 | 64×6 ＝ 384 条有向边 ＝ 384 条爻辞；🔴 这不是奇迹，是同一个「6」的两面 |
| 税的乘法性 | 三步之积 ＝ exp(β·ΔV) ＝ 两端势之比 ⇒ **能乘的税必然来自一个势函数** |
| 工作区间 | 熵率掉到 95%·ln6 处 β=**1.5**；最差卦百万步才轮到一次处 β=**3.5** ⇒ 区间 **[1.5, 3.5]**，原文 β=4 **出界** |
| 要 0.02 | 需 β≈**26.5**，而 1/最小爻位分 ＝ 1/0.04 ＝ 25 ⇒ **良心要硬到什么程度，由最中性的那条线决定** |
| 人道墙 | 删三、四两维 ⇒ 恰好 **4 块 × 16 卦**；一般律删 k 维 ⇒ 2^k 块、每块 2^(6−k) |

🔴 **这一轮最有价值的判断**：模型自噬（Var ≤ ρᵗVar₀）与系统麻木（H→0.02）是**同一个旋钮的两侧** ——
都是分布变窄。所以「装良心」和「防异化」是一件事：装不够＝无约束漫游，装过头＝再也不会改主意。
目标是一个**区间**，不是一个最大值。

🔴 **判据自纠**：原想用「下山流量降到一半」当「约束生效」的判据，算出来**恒等于 0.5**且与 β 无关 ——
可逆性逼迫上山步与下山步的平稳流量对半。判据作废，改用熵率 ＋ 最劣选项再现时间。

## 踩过的坑

- 🔴 **少给一个参数就安静地算错**：`codeOf('乾')` 只给下卦时，`TRI[undefined]` 是 undefined，
  位运算把 undefined 当 0 ⇒ 安静返回 56；六个卦名全变成 0 也不报错。已改成**缺失即抛**（P1–P3），
  正常调用不受影响（P4：乾/乾=63、坤/坤=0、乾下坤上=泰=**56 不是 63**）。
  —— P4 我第一版就写错成 63，又一次「断言值凭印象写」。
- 🔴 **特征向量不能拿「第 k 层指示向量」冒充**。第一版这么写，报了 170 条假反例。
  正解是张量积基 `v_σ(x) = Π(−1)^{σ_i x_i}`。**是判据错，不是图错。**
- 🔴 **变异测试要真能破坏结构**。M2 一开始用「左移+末位取反」，那恰好是 c 的**逆** ——
  逆元生成同一个循环群，轨道当然一模一样，测了个寂寞。改成「去掉取反」才验得出。
- 🔴 **非回溯矩阵的平凡特征值是 2|E| − 2|V| = 256**，不是 384 − 64 = 320。
- 🔴 **互卦终局判据不能写「必须不动」**。乾坤不动，既济↔未济是 2-周期。
- 🔴 **别把期望值写成脑内顺序**：`['x','y','z'].sort()` 按码位排，中文不等于字面序。
  I8 第一次就因此假红，两边都 `sort()` 才对。
- 🔴 **判据别绕远路写正则**：`/^http://////yb//.woa//.com/////w+$/` 在两次转义里反斜杠被吃掉，
  直接语法错。前缀比较 + 尾串字符集就够。
- 🔴 **页面上的核验数要能自己变**：手写「59/59」会在加了 15 条断言后还挂在那儿。
  改成 `test-hex.cjs` 落盘 `_last-test.json`，`make-atlas.cjs` 读它注入。

## 检查器与图的经验（这一轮新增）

- 🔴 **长文本放进 SVG 必须估宽**：`<text>` 在 viewBox 里不会自动换行，超出部分直接被裁成断字。
  判据：`text.getBBox().x + width > viewBox.width` ⇒ 红。五张图第一版红了 4 条，肉眼在 375 下才发现。
- 🔴 **窄屏别靠缩**：660 宽的图直接 `width:100%` 缩到 340，11px 字变 5px。
  正解是 `@media` 里给 `figure{overflow-x:auto}` ＋ `svg{min-width:600px}`，
  同时探针要区分「页面级横向溢出」和「容器内横滚」—— 后者不算溢出。
- 🔴 **图例排得太挤会被曲线压住**：plt 底部留白必须 ≥ 图例高度 + 20px，否则 polyline 直接穿过图例文字。
- 🔴 **两段文字撞车不会报错**：图 4 里「64 点闭环」和右侧「并集 192」只差 16px 就叠上了，
  只能靠看图发现。数值自洽 ≠ 版式成立。
- 🔴 **puppeteer-core 不在机器上时**，用仓库里 `../construct-cost/cdp.cjs`（零依赖，Node 内建 fetch/WebSocket）。
  但 `Page.captureScreenshot` 的 clip 字段名是 `width`/`height`，写成 `w`/`h` 会报
  `Failed to deserialize params.clip.height` —— 不会被忽略，会直接失败，这点还好。

## 这一轮新增的判据（写进探针了）

- 🔴 **「两段文字撞车」现在能自动抓**：同一张 SVG 内任意两段文字的 `getBBox()` 不得相交，
  曲线的采样点也不得落进任何文字盒。以前只能靠看图，现在 53 段文字 / 总宽 4791 一次扫完。
- 🔴 **测「零碰撞」之前先证明量到了东西**：判据旁边必须同时报「文字条数 / 包围盒总宽」，
  否则 `getBBox()` 全返回 0 时，任意两条都不相交 ⇒ 恒真式假绿。
- 🔴 **目录是手写的，最容易烂**：探针现在比对「目录里的节号序列」与「正文 h2 的节号序列」，
  并要求「本页 N 节」的 N ＝ h2 个数。这一轮就是靠它抓出「本页十节」实际有十二节、且 §10 重号。
- 🔴 **切拼图不许猜坐标**：1280×1280 的 2×3 拼图，留白宽度不固定。正解是画进 canvas 算
  「列/行平均亮度」，亮且平的那几段就是留白，切点由数据给。三张图全自动切出 6/4/6 帧。
- 🔴 **`loading="lazy"` 会让 `naturalWidth` 全 0**：探针要先滚到底逼所有图真加载，否则「16 张全部加载」
  这条会假红（这里是红，不是绿，但同样是判据没对准）。

## 图集这一轮的经验（去重 / 相似度）

- 🔴🔴 **「同一张图」不能拿整图去比它的一个角**。22 张拼图 vs 16 张单帧，整图相关性最高只有 0.51，
  全部判成「不匹配」—— 差点因此得出「一张都不重复、22 张全是新的」这个**错结论**。
  正解是先把拼图切成面板（黑缝由行内亮度标准差给出），再一块一块比，分数立刻到 0.90 以上。
- 🔴 **相关性必须连基线一起报**。深色幻灯片彼此天然相关 0.3–0.5；只看最高分，
  「18_有效能量衰减」一度对每一帧都夺冠。判据要写「最高分 − 中位基线」的**边距**，不是绝对分。
- 🔴 **相似度阈值不是先验的**：多尺度/多取景比例逐个试（0.7/0.85/1.0），取最大，
  再要求「次高」明显低于它（实测 0.898 vs 0.705 起）。只看第一名，永远看不出自己切错了。
- 🔴 **「去重」不只是不贴第二遍图，还要留下账**。三张已用的不贴图，但必须给位置卡
  （哪几帧、哪几块面板、误差多少、原图直链），否则下一个人接手时无从判断「这里为什么少一张」。
- 🔴 **探针里不许写死核验数**。上一版把 `156/156` 写进探针，加了 O 段 10 条断言后立刻假红。
  改成从 `_last-test.json` 现读 —— 写死一次，「页面读 json」这条纪律本身反而没人验了。
- 🔴 **画图脚本与页面生成器要分家**：`_panels.cjs` / `_match4.cjs` 只回答「有几块、哪块对哪块」，
  结论写进 `sources.cjs`（`ZIP_ITEMS` 的 `used` 字段），页面只负责渲染。
  三者共用一个事实来源，改一个数不会三处打架。
