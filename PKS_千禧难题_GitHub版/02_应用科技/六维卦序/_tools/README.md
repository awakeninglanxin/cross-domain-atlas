# _tools —— 图像去重与面板切分

本目录是**工具**，不是产物。页面不依赖这里任何文件，删了不影响网页。

从临时目录抢救回来的（2026-11-01）。当时写在 `%TEMP%` 里，系统一清就没了，
而这一轮最值钱的方法论恰恰在这两个脚本里 —— 所以收进仓库，路径改成命令行传参。

## 为什么要先切面板

判断「两张图是不是同一张」，三次尝试、两次结论是错的：

| 试法 | 命中 | 错在哪 |
|---|---|---|
| md5 / sha256 | 0 | 同一内容被缩放过、裁切过，字节永不相等 |
| 整图缩到 24×32 灰度做相关系数 | 0（最高 0.51） | 拿**整图**去比它的**一个角**，宽高比一拉就成两张脸 |
| **先按内容边界切面板，再逐块比** | **16/16，0.898–0.992** | —— |

⇒ **结构没对齐之前，任何相似度分数都不许用来下结论。**

## 两个脚本

### `find_panels.cjs` —— 这图是几行几列

```bash
node _tools/find_panels.cjs <图片目录> [输出json]
node _tools/find_panels.cjs _img/zip _tmp/panels.json
```

缩到 200×300，逐行/逐列算「行内亮度的标准差」。拼图的面板之间是一条完全均匀的黑带
（std ≈ 0），面板内部哪怕再暗也有内容起伏 ⇒ `std < 2.2` 的连续行/列就是分隔带。
**边界由数据给，不猜坐标。**

输出 `[{ z, W, H, rows, cols, rb, cb }]`，`rb`/`cb` 是归一化到 [0,1] 的区间，直接喂给下一个脚本。

### `match_panels.cjs` —— 每张单帧落在哪块面板上

```bash
node _tools/match_panels.cjs <面板json> <拼图目录> <单帧目录> [输出json]
node _tools/match_panels.cjs _tmp/panels.json _img/zip _img _tmp/match.json
```

每块面板缩到 20×20 灰度、零均值单位方差，做相关系数。判据写三样，缺一样就是骗自己：

1. **最高分**——`s ≥ 0.85` 才算「同」，否则只算「像」；
2. **中位基线**——深色幻灯片彼此天然相关 0.3–0.5，只看第一名某一张会「对每一帧都夺冠」，
   所以还要 `margin = 最高 − 中位 ≥ 0.15`；
3. **次高**——次高咬得太近，要么切错位置，要么真有近似重复，两种都得人看。

脚本自带两条自检：一块面板都没切出来直接报错退出（不许交空账）；同一面板被两张单帧
高分认领时打印警告（说明单帧里有近重复）。

## 本轮实测（2026-11-01，作为回归基线）

`_img/zip` 22 张 1440 级竖拼图 → `find_panels`：

```
合计 22 张，139 块面板
版式分布: {"2×1":1, "2×2":2, "3×2":9, "4×2":9, "3×1":1}
```

`_img` 里 16 帧 → `match_panels`：**16/16 命中**，s 区间 0.898–0.992，
次高 0.700–0.944，中位基线 0.348–0.507，**边距 ≥ 0.468**，
无一张面板被两帧同时认领。

命中的三张拼图是 17 / 19 / 20，各自块数与帧数吻合（6 + 4 + 6 = 16），
且**顺序逐格对应**（`s1_01`→17 的 R1C1、`s1_02`→R1C2……）。

> 这两个数是**回归基线**：改算法后应当仍得到 139 与 16/16，
> 变了就要解释清楚是图变了还是判据坏了。

# probe_entries.cjs —— 三个总入口页的验收

```bash
node _tools/probe_entries.cjs        # 42 项，截图落 %TEMP%/en_*.png
```

验的不是本目录的页面，是 `D:/AAA我的文件` 根下那三张门面：
`AAA_双门入口_分享版.html` / `AAA_演讲入口_60分钟.html` / `AAA_跨界总入口_总网页.html`。
每次往门面里加一组内容，就跑它一遍：h2 与目录锚点是否逐项对应、新链接的文件是否真的在盘上、
`#m11` 点下去是不是落在新组而不是页顶、1440 与 375 有没有横向溢出。

## 两条写错过的判据（留着当例子）

1. **整页查 `NaN` 会假红**。总网页第 258 行本来就写着「原脚本会出 NaN / 开方为负的地方一个都没偷偷修掉」——
   这是正文，不是 bug。⇒ 判占位符只许查**新插入的那一段**（`#m11` 到 `#m12` 之间），并且先断言这段抓到 800 字以上。
2. **演讲页默认 30 分钟是对的**，拿「标题里有 60 分钟」当判据必假红。
   ⇒ 正确判法是**真去点一下「60 分钟」按钮**，再看 `document.title` 重算没有，顺带核对七段色条加起来正好 60。

这两条是同一类错：判据写在了「本来就不会出问题」的位置。
判据要放在**会出问题的那一档**上。
