幻立方定相位：一个被量到 0 的增量

在 FHRR 的 27 维相位码上，把「用幻立方 27 格定相位」与随机相位逐项对比。 结论不是「有/没有优势」，是优势在哪个指标上、多大、以及代价是什么。
27 维 FHRR 绑定–解绑检索 含一份被自己证伪的结论 两份独立实现互校 数字现场重算

01结论先行

三个数，都在本页现场算出来（不是引用）。

两两内积：随机 → 幻立方
—
幻立方把「码字串扰」压到 0，随机约 0.10–0.17。这一栏幻立方完胜。
检索准确率（N=5）之比 随机/正交
—
换到真正用途（绑定–解绑）上，随机反超，不是小幅。
唯一微弱优势的 t 值
—
首测 +0.7%（t=2.30），换 12 个独立种子后掉到 t≈1。
三句话说完： ① 幻立方相位的几何只由「27 个格的值取遍 1..27」决定，幻和 42 一格都没进公式； ② 因此它等价于教科书里的 DFT 正交码本，不是新东西； ③ 而这个码本在 VSA 唯一的实用任务上，比随机相位差 3.3–4.7 倍，维度越大差得越多。
但有一小块东西是幻立方独有的，而且没被否掉：不是「表示能力」，是可校验性。 27 个数被组织成 31 条已知和为 42 的线，改一格会同时打破 3～7 条线 —— 这能定位篡改，随机相位连「该等于多少」都没有。见第 9 节。

02怎么测：把「优势」拆成四个可分别证伪的量

「结构化初始化更好」这句话太粗，一次只能测一件事。本页固定一件事：同一份 FHRR 码，只换相位来源。

2.1 任务定死：key–value 绑定后解绑检索

存 N 对：M = Σ (k_i ⊙ v_i)；取第 j 对时 u_j = M ⊙ conj(k_j)， 再在 value 池里做最近邻。这是 VSA 里最基本的用法，也是语言模型里「角色–填充」编码的原型。

2.3 相位方案

四组都取 27 个符号、27 维，唯一变量是相位来源。幻立方为31 条线全为 42的那个解（下行三层）。

两种「用幻立方定相位」的读法都测了： 一种是 θ = 2π·j·M/27（模 27，对应 27 等分）， 另一种是 θ = 2π·j·M/28（模 28，补数 28−M 恰好对应相位取共轭，与叮咚表的模数一致）。 两种都测，是为了避免「你选的映射不对」成为反驳理由。

03先排混淆：幻和 42 根本没有进入相位几何

这里有一个容易骗过自己的地方：幻立方版本的「两两内积」看起来完美得可疑。先查清这个完美是谁给的。

相位方案两两内积 均值标准差最大判定
决定性的一行：把幻立方的 27 个格随机打乱（幻和立刻不成立），再走同一套相位公式 —— 内积矩阵逐位相同（实测差值 < 1e-12，见自检 —）。
⇒ 幻性（每条线 42）在相位域完全不被使用。被使用的是「27 个值恰好取遍 1..27」这一条， 而它等价于等距量化 + 完整剩余系，也就是 DFT 基。

为什么必然如此：⟨v_j, v_j'⟩ = (1/27)·Σ_k exp(i·2π·(j−j')·M_k/N)。 求和只跑遍值的多重集，格位排列被求和吃掉。 所以「把数摆在哪个格」对相位几何完全没有影响。

04主结果：换到真正的用途上，结构化完败

下表由本页脚本现场跑出（每格 100 次独立试验，固定种子）。三条结构化曲线互相重合，重合本身就是证据。

方案 N=2N=3N=5N=8N=12 符号上限
两份独立实现互校：本页用 JS 现场算；另有一份 Python 实现（不同随机数发生器、不同语言）跑同一任务， 给出 0.983 / 0.870 / 0.504（随机，N=2/5/12）与 0.539 / 0.267 / 0.184（正交）。 两者差异在统计涨落内，结论不是某一份代码的 bug。
为什么不是「容量不够」而是「精确冒充」：结构化码本的干扰项不是弥散的噪声， 而是精确落在另一个码字上。见下一节。

05机制：100% 对 0% 的并列率

同一个数（N=5）在两种码本下的差别，不是「误差大小」，是「能不能分辨」。这一节把并列率算出来。

DFT / 幻立方：bundle 后的并列率
—
成员得分全是 1.000，最高分与次高分严格相等 ⇒ argmax 只能靠下标打破，等于抛硬币。
随机相位：bundle 后的并列率
—
每个成员都被随机小串扰推开，分数互异 ⇒ 有明确 margin 可供判断。
为什么会精确等高：正交码本下 ⟨u_j, v_i⟩ 只能是 0 或 1 这类离散值。 叠加 N 项后，正确项得 1+小量，而某个冒充项也会得 1+小量 —— 两者在同一量级、同一结构上，差别只剩噪声级的相位。 随机码本把这份「整齐」打散了，反而留出了判断余量。
顺带一个恒等式（不是码本问题）：N=2 时任何码本的 bundle 都必然并列 —— 因为 ⟨s1+s2, s1⟩ = 1+a 与 ⟨s1+s2, s2⟩ = a+1 恒等。所以 N=2 的并列率不能用来区分码本。

06维度越大，结构化越没有胜算

这一条最要紧：真实的 FHRR 用 512–4096 维，不是 27 维。若差距随维度缩小，那 27 维的结论就不能外推。

维数 d正交随机随机/正交说明
差距是放大的，不是收敛的：d 从 27 到 216，正交码本从 0.255 掉到 0.210， 随机码本从 0.852 升到 0.987，倍数从 3.34× 拉到 4.70×。
原因：正交码本的碰撞是结构性的，与维度无关；随机码本的串扰 ~1/√d，维度一涨就消失。
⇒ 在真实维度上，结构化相位的劣势更大，不会更小。
上表是离线算的（Python，d=216 时纯 Python 已偏慢），页面不重跑；本页现场只跑 d=27 那几行。 口径：固定 N=5（绝对载荷），每格 3 个种子 × 40 次试验。

07加抖动能不能救回来：没有甜区

有人会说「那就给结构化相位加一点随机扰动」。这个想法值得测，而且它有明确的最优点可找。

抖动幅度 ε检索准确率平均 |内积|读法
结果：单调爬升，然后停在随机基准上。 ε=0 时 0.254，ε=0.8 时 0.862，ε=3.14（等于完全随机）时 0.873。 没有任何一个 ε 超过纯随机。
也就是说，抖动的作用只是「把结构化逐渐稀释成随机」，中间没有「既保留结构又打破并列」的窗口。 想要 0.87，直接取随机就行，不必先造一个幻立方再把它搅乱。

08我自己那份「显著优势」，被自己推翻了

首测时确实出现过一个微弱优势：结构化 key + 随机 value，比全随机高 0.7 个百分点，t=2.30。 这个数差点被我写进结论。换种子后它消失了。

复现批次N=3N=5N=8判定
12 个独立种子合并（N=5）：差值 +0.0034，t = +0.97，结构化胜 7/12 次。 七比五，和抛硬币没有区别。
这就是「没测过就只是设计选择」的具体样子：第一次测出来的显著，多半是种子挑出来的。 只有换一批种子还在，才能叫优势。

09那么幻立方到底能贡献什么：可校验性，不是表示能力

上面的否定只否掉了「相位几何」这一层。幻立方里真正随排列变化的东西是别的一样：格与线的关系。

27 个数被组织成 31 条线，每条线关于 42 有一个已知期望值。这带来一个随机相位完全没有的能力： 看到一个阵列，能判断它是不是被改过，并且能定位改在哪。

格的类型个数所属线数改这一格会打破几条线
唯一能守的说法：「把 27 个数排成幻立方后，任何单格篡改都会同时打破 3～7 条线， 因此不必知道原阵列也能定位改动位置（签名由所属线集合给出，27 个格签名互异）。」
这是真的，而且随机相位给不了 —— 随机码本没有「期望值」这个概念。
但必须同时说清它的边界： ① 这个能力作用于数组本身，不作用于绑定后的向量 —— bundle 一叠加，格结构就没了； ② 它不提升任何检索性能（第 4 节已经量出来，没有提升）； ③ 所以正确的定位是「校验层」，不是「表示层」。 拿它去替换随机相位，等于用一个校验码去干编码的活。
