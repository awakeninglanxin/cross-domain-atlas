01两条路，两个答案

方向问的问题答案

先说结论的分野。① 是真能独立成立的：它是一个纯粹的数组校验器，不依赖相位、不依赖 VSA、不依赖任何模型， 今天就能拿去查「这份 27 格数据是不是被改过」。② 是半个负面结论：能在 bind 链上守住，但在 VSA 真正要用的 bundle 上严格归零。两条都要如实写出来。

02校验层：27 个格各自的「身份证」

31 条线 = 27 条轴向 + 4 条体对角。每个格属于几条线，就是它的「线签名」——这是能定位的前提。

8
穷举 k≤7 零命中 + 构造出 8

签名互异是定位的全部前提：27 个格给出 27 个不同的签名，所以「哪几条线破了」本身就编码了「哪个格被动了」。 这不是我额外加的机制，是 3×3×3 的线结构自带的。

一个容易说错的地方：中心是 7 条没错，但「角格 4 条、其余 3 条」里的「其余 18 个」不是同一种， 它们是 12 个棱格 + 6 个面心，签名大小都是 3 但具体组合不同——这 18 个之所以能分辨，靠的是组合而不是大小。

03检测 100%，定位却掉得很快

随机改 k 个格（各加 ±1..±5 的随机增量），看「有没有线破了」和「能不能指回那 k 个格」。

篡改格数 k检测率 定位率含义
为什么检测率能到 100%，定位率却塌。检测问的是「破线集合非空吗」，定位问的是「候格集合恰好等于真实集合吗」。 随 k 增大，破线集合变大，而「签名 ⊆ 破线集合」的格越来越多——真凶混在一堆无辜者里。这不是判据太严， 是 信息量本身不够：k 个格只产生 ≤ 4k 条被破坏的线，反推 k 个位置，k 大时必然多解。
换算法能好一大截，但不是白拿的。上图那条曲线只用了一条组合判据（签名 ⊆ 破线），扫一遍就完事。 改用最小命中集 + 线性方程求解——31 条线的约束全进方程组，解出的增量还要保证没破的线仍然是 42—— 实测定位率变成 100 / 100 / 100 / 99.5 / 97.0 / 86.5 / 76.0 / 61.5%（k=1..8，每档 200 例）。 代价是每次要解一个 ≤9 元的小方程组；换回来的不只是「哪几格」，还有每格该改成几。 这套东西已经做成独立工具 magic31.py，不依赖本页也能跑（见第 08 节末尾）。

从幻立方开始：31 条线的和都等于 42。

为什么 8 个角格能完全隐形

给 8 个角格按 符号 = (−1)^((x+y+z)/2) 加上 ±δ，其中 x,y,z ∈ {0,2}。证明只有一句话：

  • 轴向线：每条轴向线要么不含角格（另两个坐标里有 1），要么含恰好 2 个角格，而这两个角格在第三个坐标上相差 2，符号相反 ⇒ 和不变。
  • 体对角线：每条体对角线穿过 2 个角格 + 中心，那 2 个角格的符号也相反 ⇒ 和不变。

所以这不是「很难被发现」，是在 31 条线上严格恒等。

唯一性也验证了。把「每条线含 0 个或 ≥2 个被改格」当必要条件先筛，C(27,8)=2,220,075 个子集里只剩 1 个候选； 再对这个候选算 31×8 的零空间，维数 1。也就是说：支撑为 8 的隐形扰动，有且只有 8 个角格这一种。 再加上「k≤7 时穷举 888,030 个子集零命中」，最小隐形扰动恰为 8。
这条结论的工程含义。「单格篡改必被发现」是可证的；「想不露痕迹地改」至少要动 8 个格、且必须恰好是 8 个角格、且符号必须成对相反。 攻击面窄得可以枚举。这是校验层真正能卖的东西——不是「安全」，是「篡改成本可计算」。

05刀锋：31 是唯一可解的那一点

既然 31 条线有盲区，加几条面对角不就补上了？加了就解不出来了。这一步是严格判定，不是搜索失败。

37 条线为什么无解：整族解只有 3 个数

精确有理数消元给出：特解取值 {0, 14, 28}，零空间基取值 {−1, 0, 1}。于是任意解都是

v(t) = x₀ + t·n₀     每个分量只能取 {14−d, 14, 14+d}，d = 14−t

实测 t 从 −5 扫到 +5，每一档的不同值个数都恰好是 3。而 1..27 的排列需要 27 个不同的数。

所以「不变量越多越好」在这里第二次被证伪。27 条线时中心可以是 5；31 条线时中心被锁死为 14、但还有 1..27 的排列解； 再加 6 条面对角，解族直接塌成一条等差数列——不是变紧，是变得不可能。 31 是唯一同时满足「有排列解」和「盲区最小」的点，两边都只有一步之遥。

06约束层：代价取决于「耦合半径」，不取决条数

方向②。27 维 FHRR，27 个码字，任务固定为 bind→bundle→unbind→全码本最近邻，N=5，4 批独立种子。

固定自由度 m剩余维数 冻结 m 个位置局部守恒 m 条 全局绑定 m 条

同样是丢掉 9 个自由度，为什么差 0.12

三种做法都让零空间从 27 维降到 18 维，但丢掉的东西不一样：

  • 冻结位置（前 9 个分量恒为 0）：这 9 个位置在所有码字里完全一样 ⇒ 变成一段公共常量， 内积均值从 — 涨到 —，码字互相「长得像」。
  • 全局绑定（u_r = −a_r·u₂₆）：9 个位置都由同一个变量决定 ⇒ 它们彼此强相关，但至少不是常量。
  • 局部守恒（每组 3 个分量和 ≡ 0）：每组的第三个由前两个决定，每个位置仍在独立变化，不产生公共分量。
这就是「有真正免费的午餐」的地方。把 9 条局部守恒约束加进随机码本， 准确率从 — 变到 ———差 —，在种子涨落之内。 换句话说：「每条线和 ≡ 0」这件事可以不花钱拿到。
但别高兴太早。免费的前提是「模守恒」（和 ≡ 0 (mod 27)）。如果改成「整数和严格等于定值」， 就落进冻结那一侧——因为定值把均值锁死，所有码字都带上同一段常数。幻立方那 31 条线是整数和 = 42， 属于后者。这一步是整页最容易被忽略的差别。

07决定性的一条：bind 下 100%，bundle 下 0%

约束能不能在运算之后还活着，决定了它有没有用。VSA 有两个基本运算，结果完全相反。

约束条数bind 后存活 bundle 后存活对照

为什么必然如此

bind 是逐元素相乘，相位上就是相加。若每个码字都满足「某组三个分量相位和 ≡ 0」，那么两者的 bind 结果 三个分量分别是 θ+θ'，和仍然是 0+0 = 0 ⇒ 严格封闭。

bundle 是逐元素相加（复数相加）。e^{iθ₁} + e^{iθ₂} 的相位是加权平均，不是 θ₁+θ₂。 平均之后就落回随机水平：1/27 ≈ 3.7%。

这条把方向②的上限钉死了。VSA 的任何检索都必然要做 bundle（把多个 item 叠加进一个向量）。 所以「把守恒约束嵌进码本」在真正的用途上一条都留不下。 它只在纯 bind 链（例如多层绑定、不叠加）里有效——那是一个很窄的场景。

08落地规格：这个校验器能做什么

方向①已经足够独立，可以把它的能力写成一份不含糊的规格。

能力能不能依据
判断一份 27 格数据是否被改过能 除非改动恰好是 8 角格棋盘图样
单格篡改的定位能，100% 27 个线签名两两互异
2~4 格篡改的定位能，几乎全对 方程求解实测 100% / 100% / 99.5%；只用签名筛法只有 97.6% / 88.8% / 70.8%
5~8 格篡改的定位九成降到六成 方程求解 97.0% / 86.5% / 76.0% / 61.5%（k=5..8，每档 200 例）
8 角格棋盘的检测不能 31 条线严格恒等；穷举确认唯一
保护叠加后的 bundle完全不能 叠加后格结构不存在，无从校验

所以正确的用法是把两层分开

表示层：纯随机相位码本            → 检索性能 0.92（不用扛任何约束）
校验层：31 条线，旁路运行          → 只查"索引表 / 权重文件 / 数据阵列"有没有被动过
连接处：码本第 j 个向量 = f(格值)   → f 必须是单射，否则校验层保护的不是真实数据
那句「把不变量编译进解码」的正确落点，其实就是这个连接处。不是把不变量塞进码本（第 06、07 节已经否掉）， 而是在生成 token 的那一刻检查「这个数组还能不能通过 31 条线」。这两件事差别很大： 前者要求不变量在叠加后存活（做不到），后者只要求在写下来的那一刻成立（完全可做）。
已经落地成一个独立工具：magic31.py。单文件、纯标准库、可 import 也可当命令用，不依赖本页： 
python magic31.py check 1 2 3 ...      # 27 个数：破几条、哪几条、差多少、最少动几格（含该改成的值）
python magic31.py check --file arr.txt   # 从文件读（空白/逗号分隔都行），加 --json 出机器可读
python magic31.py fix --file arr.txt     # 直接输出修正后的数组（报告走 stderr，可接管道）
python magic31.py fix --file arr.txt --out ok.txt   # 或写进文件，不动原文件
python magic31.py null                   # 打印 4 维盲区的基，每条都逐行验算
python magic31.py tamper --blind         # 造一份「31 条线全过但数组已经错了」的样例
python magic31.py selftest               # 55 项自检：秩、盲区、最小性、定位率、修正、变异测试
python magic31.py measure --m 200        # 重跑上面那条定位率曲线
退出码：0 = 通过且是 1..27 排列｜1 = 有破线｜3 = 全过但不是排列（落在盲区）｜4 = 修不了｜2 = 输入错误。

fix 不是「随便修成一个能过线的数组」：它默认还要求修完仍是 1..27 的排列， 并按「改的格数少 → 改动量小 → 保排列」排序。实测在 ≤3 格的篡改上解唯一， 所以排列这一条在这一档是独立复核，不是筛子（这一点也写进了自检，免得把它说成筛子）。 8 角格盲区上它拒绝给修正并明说「落在盲区、无法唯一还原」——不装能修。
要嵌进别的项目，用同目录的 magic31_api.py（整文件 46 行，5 个函数、逻辑就 5 行，不含算法）。 
import magic31_api as m
m.ok(state)        # 31 条线全过 且 是 1..27 排列？
m.broken(state)    # 破了哪几条线（空列表 = 通过）
m.repair(state)    # 返回修正后的 27 个数；修不了返回 None
m.make(7)          # 生成一个合法幻立方
盲区上三个信号同时到位：ok=False、broken=[]、repair=None —— 检测不到、也修不了，三个答案一致，不会有一个说「没事」。

09不能守的三句话

这三句如果收不住，这一页就会变成又一个吹过头的说法。

① 不能说「幻立方可以防篡改」。它只能发现支撑 < 8 或不是 8 角格图样的改动。 一个知道结构的对手可以精确构造出查不出的改法，成本已在本页枚举清楚。它是体检，不是锁。
② 不能说「给码本加守恒约束不花钱」。免费有严格前提：模守恒、且局部（每位置仍独立变化）。 换成整数定值或全局绑定，代价立刻出现（第 06 节三条曲线）。
③ 不能说「约束能跟着 bundle 一起走」。bundle 之后存活率是 0%。 任何声称「在叠加态上还能校验不变量」的方案，必须先解释它怎么绕过这个 0%。
