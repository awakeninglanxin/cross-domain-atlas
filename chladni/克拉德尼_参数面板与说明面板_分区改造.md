# 参数面板 / 说明面板：把文字搬出去，把控件全摊开

> 2026-10-24 老师原话：
> 「你改一下参数面板，把文字说明放在另一个面板，让参数面板只有**全部类型展开可调**的
> 画图或输入值，不然我每次要点开那些收起的参数子卡」
> 「`AAA_克拉德尼_7节点三振子_响应式.html` 同理这个参数面板也改」
>
> 两个页面同源模板 ⇒ 一次改造、两页同构。

---

## 一、先说结论（四句话）

1. **2026-10-23 那套折叠（节级 `h2.sf` + 说明条 `details.noteFold` + 「展开全部说明」按钮）
   整套删掉**。参数面板里现在**没有一个折叠元素**，不是「默认全开」，是 DOM 里就不存在。
2. 解释文字不是复制，是**搬家**：同一个 DOM 节点 `appendChild` 到左侧新面板 `#noteP`。
   ⇒ 带 id 的段落照旧被 JS 写字（`$()` 按 id 找，跟它在哪个容器里无关）。
3. 参数面板只留**滑块 / chip / 输入值 / 数值表**；「为什么…」这类正文全在 `#noteP` 里，
   默认收起，点「说明（N 条）」或按 `N` 打开，状态记 localStorage。
4. 搬走 93 条（Keely 页，2026-10-24 加「角向阶 m」那段说明后 +1）/ 70 条（7 节点页），**一个输入控件都没动**
   —— 34 个 / 28 个 `input` 全部仍在参数面板里。

---

## 二、问题在哪：折叠本身没错，错在「每次都要点」

上一轮（2026-10-23）面板里 60 多条解释摊开就是一整屏文字，所以做了两套折叠：

| 那套东西 | 当时的目的 | 现在的问题 |
|---|---|---|
| `.sec > h2.sf[data-open]` + `.sfBody` + `.sfHint` | 整节收起，标题下写「已收起 · 3 滑块 · 5 按钮（点标题展开）」 | 想调**任何**一个滑块都得先点一次标题 |
| `details.noteFold`（运行时把 `p.note` 包成 details） | 段级收起，标题自动取段首粗体 | 想看一句原理得点一次 |
| 顶部 `#btnFoldAll`「展开全部说明」 | 一次全开 | 全开之后面板 ≈ 13 600 px 长，滚到下一个滑块要滑很久 |

本质矛盾：**「收起省地方」和「随时可调」是打架的**。
老师的选择是「随时可调」⇒ 折叠必须让位给「搬到别的地方」。

---

## 三、做法

### 3.1 分区不是手写，是运行时按「有没有控件」判

```js
/* 唯一硬闸：框里有真输入控件（input/select/textarea）就不搬 */
function hasCtl(el){ return !!el.querySelector('input,select,textarea'); }
```

搬什么：节的直接子元素里 `p.note` / `.note` / `details` / `figure` / `.mh` / `.wvfig`，
**再加**一节里**任意深度**剩下的 `p.note`（有的塞在 `.card` 里，只扫直接子元素会漏）。

不搬什么：

| 不搬的对象 | 原因 |
|---|---|
| 任何含 `input/select/textarea` 的框 | 搬走一个滑块 = 老师再也调不到它，比折叠严重得多 |
| `.preTour` 预设卡里的说明 | 那是卡片自己的说明，搬了卡片塌成空壳 |
| `.note` 但只有一个**带 id 的状态条**（如 `#tourNote`「已锁定冷暖对流」） | 它是实时状态，不是正文；留着 |
| 整节搬空后剩下的空壳 | 直接整节 `removeChild`，不留「只有标题」的空节（点开以为坏了） |

### 3.2 为什么 `button` **不算**控件（这条是踩出来的）

第一版 `hasCtl` 写成 `input,select,textarea,button`，结果：

> 「驻点环」那块 `details.mec` 里挂着一颗 `<button id="btnMdStag">推导 md</button>`
> ⇒ 整块被判定为「带控件」⇒ 它连着里面 3 段正文**留在参数面板里**，
> 而老师的验收线是「参数面板里一条说明都不剩」。

所以判据收紧成：**只有真输入控件才算**。`button` 全是 chip / 「推导 md」这类旁支入口，
搬进说明面板照样能点。代价是：万一某个 chip 是「改参数」的，它也会被搬走
—— 本页实测 `ctl = 0`（一个带 input 的说明块都没有），这个代价目前为零。

### 3.3 面板位置：左列 + 必须藏掉「实时反馈」

```
#noteP{ position:fixed; left:12px; top:12px; bottom:150px; width:396px; z-index:79 }
body.np-on #lhud{ display:none }
```

- **`bottom:150px` 是量出来的**：左下「一键发声」那两排（`#soundDock` 底 52、约 100 px 高）
  顶到 y ≈ 150（902 px 高视口实测 `sound.top = 766`，即离底 136），说明面板下沿 150 刚好让开。
- **必须藏 `#lhud`**：它 `bottom:150`、最高 470 ⇒ 占 y 约 280–750，和说明面板整块重叠。
  不藏就是两张半透明深色卡叠着，谁也读不清。
- 因为「藏了实时反馈」可能让人以为坏了，头部加了一颗小字
  「**· 实时反馈暂藏**」（`#notePLh`，暗金 10.6 px），关掉说明就回来。

## 四、踩过的四个坑

| # | 症状 | 真因 | 处理 |
|---|---|---|---|
| 1 | 探针报「说明面板不可见」，可截图明明是开着的 | `position:fixed` 的元素 **`offsetParent === null`** —— 它对固定定位没有意义 | 判据换成 `getComputedStyle(el).display !== 'none'` |
| 2 | `TypeError: (s \|\| "").replace is not a function` | `.map(npNorm)` 会把 `(元素, 下标, 数组)` 三个参数都传进去，`npNorm` 只收字符串 | `.map(e => npNorm(e.textContent))` |
| 3 | 参数面板冒出横向滚动条（`Δ = 25 px`） | 折叠时那些行 `display:none`，**从来没被排版过**；全摊开后 `#vCoupLink`（「mouth（钢环 0.045R）」那条）实测 **345 px > 内容宽 336** | `.lb .v{flex:0 1 auto; min-width:0; overflow-wrap:anywhere}` —— 允许收缩 + 断词 |
| 4 | 说明面板压住「一键发声」 | 下沿设小了（变异测试把 150 改成 40 ⇒ `note.bottom=862` 撞上 `sound.top=766`） | 由探针的 **rect 相交** 判据钉住，不靠肉眼 |

> 坑 3 值得单记：**被折叠藏起来的布局等于没有测过**。
> 折叠一拆，所有「宽度刚好卡住」的行都会露出来 —— 这类问题只能靠「scrollWidth − clientWidth ≤ 1」查，
> 肉眼看截图看不出来（它只是多了一条 2 px 的滚动条）。

## 五、判据（`_probe_secfold.cjs`，28 → 70 项，两页各一遍）

这个文件原来是「节级折叠探针」，测的是本轮被删掉的功能 —— 直接改写，不留假绿。

| 组 | 钉的是什么 | 硬在哪 |
|---|---|---|
| A 无折叠 | `details.noteFold = 0`、`[data-sf]/​.sfHint/​.sfBody = 0`、屏上无「已收起 / 点标题展开」、所有 `.sec` 可见、`#btnFoldAll` 不存在 | 不是「默认全开」，是**元素都不存在** |
| B 控件守恒 | 全文档 `input` 数 = **源文件里的个数**（Keely 34 / 7 节点 29）；说明面板里 0 个 | 搬丢会少、复制会多，两头都抓 |
| C 一条不丢 | 全文档 `.note` 数 = 源文件条数（**105 / 83**）；`#panel p.note = 0`；说明面板里只剩 `SPAN#tourNote` 这种状态条；7 块 `details` 全展开；无空节 | 用**源文件计数**做基准，不用魔法数 |
| D 开关 | 默认关 → 点开可见 → `body.np-on` → `#lhud` 被藏 → 与 `#soundDock` / `#viewBar` **rect 不相交** → ✕ 能关 → `#lhud` 回来 | 几何用 rect 相交算，不看截图 |
| E 排版 | 两列都 `scrollWidth − clientWidth ≤ 1`、都真的可滚 | 坑 3 的入口 |
| F 跳转 chip | 点「机械布阵」（整节已搬走）⇒ 自动开说明面板并滚到那节；点「七管 3D 布阵」（还在面板里）⇒ 只滚不开 | 两条路径都要通 |
| G 不变式 | 全页 id 唯一（408 个 / 408 个不同） | 搬家**不许**用 clone（同 id 打穿是老坑） |
| H | 零未捕获异常 | — |

### 变异测试（证明判据有牙，不是恒真）

| 变异 | 期望 | 实测 |
|---|---|---|
| M1 把 `appendChild(el)` 改成 `appendChild(el.cloneNode(true))`（复制代替搬家） | 条数翻倍 / id 重复 | `.note` **105 → 205** ⇒ 红；重复 id **23 个**（`nCombo`/`nUniq`/`nGcd`…）⇒ 红；连跳转也红（第一份副本拿走了 `id`） |

## 七、快捷键与状态

| 操作 | 效果 |
|---|---|
| 点 `说明（N 条）` / 按 `N` | 开 / 关说明面板（`N` 在输入框里打字不触发） |
| 点面板头的 `✕` | 关 |

## 八、不算 / 没做

1. **没做「说明面板跟着参数面板联动高亮」**：滚参数面板不会同步滚说明面板。
   两列是独立滚动的 —— 真要联动得双向同步、还要防回环，这一轮不做。
2. **没做搜索**：93 条正文里找一句话只能靠节标题和浏览器 Ctrl+F（`display:none` 的
   面板里 Ctrl+F 是找不到的，所以要先打开说明面板 —— 这是已知不便，不是 bug）。
3. **手机档没实测**：`@media` 里把说明面板改成整屏抽屉（`left/right:8px`），
   只做了 CSS，没在真机上量过。列账。
4. **`.preTour` 里的说明没搬**（会塌卡片）⇒ 那几张预设卡自带说明仍在参数面板里。
   它们是「卡片的文字」，不是「节的正文」，目前留着。
5. 旧的 URL 参数 `?secs=open` 现在**什么都不做**（折叠没了）。老探针还在传，
   无害，但别指望它把面板「打开」—— 现在面板默认就是全开的。
