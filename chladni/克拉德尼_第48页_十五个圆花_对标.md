## 3. 判据：亮块是**腹点**，不是节点

这是整篇最要紧的一条，也是最容易搞反的一条。

- 在**金属板**上，粉被振离腹点，落在**节线**上 → 图里白线 = 节线（书 p.55 那 40 格就是这样）。
- 在**eidophone** 上，装置是"空腔 + 侧管"，粉被气流带着走，堆在**振动最大**处 → 图里白堆 = 腹点。

**证据就在第 7 格**：整格只有一个中心大堆。基模 (0,1) 没有内部节线，不可能在正中间生出一个节点；
但它的**腹点就在正中间**。所以亮块 = 腹点，判据成立。

由此得到两条读数规则：

1. **数一圈亮堆的夹角 → n**：`n ≈ 180° / 相邻两堆夹角`（节直径与节圆相交，腹点成对出现）。
2. **数亮环层数 → s**：腹点带夹在节圆之间，内部节圆数 = s−1。

第三条是交叉验证：第 i 个节圆在 `r/R = j_{n,i} / j_{n,s}`。这个比值对 n 敏感
（n=3 时内环在 0.50R，n=6 时在 0.66R），可以反过来排除 n。

**为什么"少数一堆"很正常**：人声从**侧管**灌入，激励本身不轴对称，总有一两个腹点被压制。
所以不要因为"应该是 6 堆、只看到 5 堆"就否定这个 n。

## 4. 测量是怎么做的（可复现）

原图：手机翻拍书页，整幅 `790 × 1920`，**每格圆只有约 92 像素**。步骤：

```bash
# 1) 切格（投影法定位方盘 5×8 网格；圆盘按等分切）
python _dev/analyze48.py     # 第一版：连通域，被 JPEG 噪点带偏，弃用
python _dev/peaks48.py       # 第二版：重模糊 + 局部极大值，仍不稳
python _dev/angular.py       # 第三版：环带按 θ 展开做 FFT，主谐波 k
python _dev/fit48.py         # 第四版：候选 (n,s) 合成场与照片对比打分
```

**四版都没有资格单独定案**，原因写在下面第 6 节。最终结论是
**"FFT 的 k（角向谐波）+ 人工数堆 + 环半径比值"三者互相对上才写进表里**，
对不上的行标 ○。举两个例子：

- **#3**：两个环带的角向 FFT 都是 **k=8**，第二名只有 0.25（很强），肉眼也是 8 条，
  环半径无明显分层 → (4,1)，●。
- **#3 的反面 #11**：环带 FFT 得 k=9/11，肉眼数 10 堆，两条对不上，**只能标 ○**。

## 5. 方盘那 40 格（p.55）

p.55 的 40 格（5 列 × 8 行）是**方板**图版，正文说 "all two- or fourfold because they were
produced on a square plate"。这一版**只做图像档案，不逐格标 (n,m)**，理由：

- 纯格子型能数（竖线数 = m、横线数 = n，f ∝ n²+m²），但只占一部分；
- 对角型 / 弯曲型是**差式组合** `cos(nπu)cos(mπv) − cos(mπu)cos(nπv)`，节线是曲线，
  投影法数不出线数（我试过 `_dev/grid55.py`，对角格会给出 10⊥8 这种假数）。

所以只按族分类讲（见网页 §04 的说明框），**不硬凑每格的 (n,m)**。
另外 4 格（4-1、4-2、5-1、5-2）被原截图上的"55/66 目录"悬浮按钮压住了，
网页里已灰底标注"被原截图按钮压住"——**这 4 格的内容我没看到，不猜**。

## 6. 这批照片的分辨率上限（必须说清）

| 能做到 | 做不到 |
|---|---|
| 判出**旋转对称阶** n（±1） | 判出唯一的 s（±1，且 n 大时更难） |
| 判出**环的层数** | 判出环半径到 0.02R（书页略斜，圆被压成椭圆） |
| 判出"是螺旋/十字/星形/罗塞塔"这类**族** | 判出**绝对频率**（无比例尺、无音高记录） |
| 判出"亮块在腹点还是在节线" | 判出**驱动相位**（同一模可以有多种堆法） |

一句话：**92 像素的格子，能反推"是哪一族、大概哪个阶"，反推不出"这个模在 531.0 Hz"。**
凡是我在网页上标灰点的行，都是这一条的直接后果。

## 7. 历史记录：上一版为什么写错了

上一版（同一天早些时候）写的是：

> 书页照片在元宝分享页里指向私有 COS 桶，直连 / 带 Referer / 带 UA 全 **403 Access Denied**，
> 所以 15 格是按"3×5 + m=n 标灰"的结构重建的，不是照照片描的。

403 这件事是真的（分享页的 `<img>` 用的是带时效签名的 URL），
**但"按结构重建"这个决定是错的**——因为：

1. 3×5 并不是 s×n 矩阵（见第 1 节），结构一猜就错；
2. 边界条件猜成了"自由边板"，而这批图是膜（见第 0 节）。

**教训**：照片拿不到时，正确做法是**只写方法、不填结果**；
一旦用"结构 + 假设"把 15 格填满，读者没法分辨哪一格是看的、哪一格是猜的。
这一版给每行都加了置信度标记，就是为了让这件事可分辨。
